## 1. Herdr's native app

### 1.1 What Herdr is, and where it lives

- **Two generations.** Herdr 1 (`herdrdev/herdr`, formerly `ogulcancelik/herdr`) is "the runtime your coding agents live on": a terminal multiplexer with workspaces, tabs and panes, agent status per pane, a background server, SSH machines, a socket API and plugins, "one rust binary, no electron — runs in whatever terminal you already use" ([README](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/README.md?plain=1#L29-L38)). It had 48,886 stars on 2026-11-07. Herdr 2 is two new repositories, both with their first commits on 2026-10-23, Apache-2.0, maintained by Can Çelik (`ogulcancelik`): **herdr-core** (`hc`), which "runs programs and coding agents in terminals that stay alive after you leave" and "draws nothing" ([README](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/README.md?plain=1#L1-L6)), and **herdr-app**, "the Herdr 2 desktop app (`herdr-app`): a native GPUI client of herdr-core" ([AGENTS.md](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/AGENTS.md?plain=1#L1-L5)). herdr-core's guide forbids copying Herdr 1's code: "Fresh code. Do not copy from Herdr 1" ([AGENTS.md](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/AGENTS.md?plain=1#L28-L31)).
- **Pace.** herdr-app has 307 commits since its first on 2026-10-23, herdr-core 136 since the same day (counted in the clones); herdr-app had 2,262 stars on 2026-11-07. The app's changelog starts at 0.1.4 on [2026-10-23](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/CHANGELOG.md?plain=1#L196) and reaches 0.1.13 eleven days later.
- **Platforms.** macOS on Apple silicon, Linux on x86-64 and ARM64 ("Linux needs a desktop session and a working Vulkan driver"), and Windows x64 ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L5-L36)). No mobile client appears in either repository or on [herdr.dev](https://herdr.dev), whose only remote reach is SSH machines.
- **Docs.** The app's documentation is three pages ([mods](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/docs/mods.md), [commands](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/docs/commands.md), [security](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/docs/security.md)) and one guide, `defaults/AGENTS.md`, which the app writes into every user's `~/.config/herdr-app` on every start "so people and agents work from one source of truth" ([mods.md](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/docs/mods.md?plain=1#L5-L7)). Most of this section quotes that guide, cited below as *the guide*.

### 1.2 What it's built with

- **Not a web view.** The window is Rust on GPUI, Zed's GPU UI framework, through the `gpui-pre` 0.3.8 crates, patched in `vendor/` ([Cargo.toml](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/Cargo.toml#L18-L22), [L71-L94](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/Cargo.toml#L71-L94)). Mods (1.5) are JavaScript in QuickJS, through Longbridge's `gpui-kit` and its `gpui-shell`, vendored at `1ccf011` ([vendor Cargo.toml](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/vendor/gpui-kit/Cargo.toml#L1-L2)). gpui-shell says of itself: "**It is not an Electron or a Tauri.** There is no WebView, no DOM, no HTML or CSS, no browser engine, and no Node.js. A script never renders. It describes an interface once, and Rust replays that description into real GPUI elements on every frame after it" ([gpui-shell README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/vendor/gpui-kit/crates/shell/README.md?plain=1#L14-L20)), and calls itself "at milestone M0: a feasibility baseline, not a stable interface" ([L27-L28](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/vendor/gpui-kit/crates/shell/README.md?plain=1#L27-L28)). The guide to mods: "You can't: use HTML, CSS, a web view, Node APIs or `setTimeout`" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L35-L37)).
- **A small core, everything else mods.** "The app's core (the model, machine layout documents, commands, and shared mod APIs) stays small; everything else is mods", with three questions a feature must answer yes to before it goes in the core ([AGENTS.md](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/AGENTS.md?plain=1#L15-L29)). "Nothing in the default interface is special: the spaces sidebar, the agents list, the tab bar, menus, dialogs and notifications are built from the same parts you have" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L10-L15)); 21 mods ship in [`defaults/mods`](https://github.com/herdrdev/herdr-app/tree/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/mods).

### 1.3 Processes

- **Window and core.** "The window arranges terminals. The core runs them. Closing the window leaves them running; closing a pane or tab ends its terminals" ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L59-L61)). The app doesn't carry a core: it uses the one installed, or installs the core's release ([`core_bin.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/core_bin.rs#L1-L8)). On macOS the core became an app of its own, Herdr Core, in 0.1.13, so that macOS asks once for local network and microphone access for programs in its terminals ([CHANGELOG](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/CHANGELOG.md?plain=1#L7)).
- **The core keeps terminals in holders.** "Holder processes own the terminals so a core restart or update can leave programs running" ([core security](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/docs/security.md?plain=1#L11)). Its rule: "Core is a runtime, not a multiplexer. If a feature only makes sense with a layout or a workspace to return to, it does not belong here" ([AGENTS.md](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/AGENTS.md?plain=1#L22-L26)).
- **One connection, framed.** The app keeps "one framed connection to herdr-core through `hc connect`: JSON-RPC on channel 0, terminal byte streams on their own channels" ([`hc.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/hc.rs#L1-L2)) and names the core methods it uses: `terminal.run`, `terminal.list`, `terminal.kill`, `terminal.label`, `terminal.attach`, `terminal.keep`, `doc.get`, `doc.set`, `events.subscribe` ([L181](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/hc.rs#L181)). The core listens on a Unix socket (a named pipe on Windows); a connection starts as line-delimited JSON-RPC 2.0, and `hello {framed: true}` switches it to frames of `[channel u32 LE][kind u8][len u32 LE][payload]` with kinds DATA, CREDIT, CLOSE, RESIZE, FOCUS, FACTS and AUTOMATIC_INPUT ([API](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/schema/README.md?plain=1#L21-L58)). The whole API is an OpenRPC document generated from the Rust types, and "The API only grows": a test fails on any change that would break a client of the last release ([L1-L19](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/schema/README.md?plain=1#L1-L19)).
- **Terminal streams.** `terminal.attach` returns a channel; the core sends a first paint (the current screen, optional history, the latest status and title), then the program's raw output; the viewer sends keys as DATA, and RESIZE, FOCUS and FACTS as they change; the last active viewer sets the size ([L62-L72](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/schema/README.md?plain=1#L62-L72)). Flow control is by credit: 256 KiB to start, and "A viewer that falls more than 4 MiB behind gets a fresh repaint instead of the backlog. A stalled stream never blocks channel 0 or other streams" ([L103-L106](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/schema/README.md?plain=1#L103-L106)).
- **Agents and status.** Herdr knows agents only by what their program reports: "An agent can say it is working, done, blocked, or in error through OSC 7501, the Program Status Protocol" ([core README](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/README.md?plain=1#L106-L111)); "No screen detection, no agent registry, no vendor-specific logic" ([AGENTS.md](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/AGENTS.md?plain=1#L34-L36)). Weave's TUI already reports OSC 7501, which it attributes to Rex's spec ([`program_status.rs`](../../tui/src/program_status.rs#L1-L6)). Agents started from inside a core terminal with `hc run` become its children, which can report back with `hc send` and be waited on ([core README](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/README.md?plain=1#L68-L92)).
- **Other machines.** `hc machine add` adds an SSH machine, which needs `hc` there; "Your local core brings its terminals into the same list" ([core README](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/README.md?plain=1#L94-L104), [machines](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/docs/machines.md?plain=1#L8-L22)). "Remote work keeps running when your local window closes or your laptop sleeps" ([app README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L63-L71)).
- **A control socket for agents.** `herdr-app do <command>`, `ls`, `commands` and `status` "drive a running window from a shell (agents, tests) over `$HERDR_APP_HOME/herdr-app.sock`, one JSON line each way" ([`control.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/control.rs#L1-L3)); `herdr-app shot` saves the last rendered frame as a PNG ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L63-L72)).

### 1.4 The layout model

There are two trees: the *layout*, which arranges the window, and each *tab*'s split tree, which arranges its panes.

- **Spaces, tabs, panes** (Herdr's words). "A **space** holds work on one machine, usually in one repo. Each space has **tabs**. Split a tab into **panes** to put terminals or mod panels beside each other" ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L42-L45)). A space nobody named is called after "its repo, else its folder" and follows its first terminal; a tab is "a piece of work in a space: its terminals and how they're split right and down"; a pane is "a terminal on screen, or a **mod** beside them (a markdown viewer, a board, a git panel)", which "splits, zooms, closes and gets a header like any pane … and is saved with its tab" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L106-L137)). A tab can be *settled*: "put away on this screen, still running" ([L124-L127](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L124-L127)). The shipped `worktree` mod makes git worktrees spaces, nested under their repository's space in the sidebar ([L822-L833](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L822-L833)).
- **The split tree.** A tab's `root` is "a row/column tree of terminal blocks" ([`model.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/model.rs#L11-L25)), the same `Node` type layouts use: a node is a `block` or a `row`, `column` or `stack` of children ([`layout.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/layout.rs#L273-L291)), and a block's content is one of four shapes ([L9-L31](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/layout.rs#L9-L31)):

  ```rust
  pub enum Content {
      Terminal { terminal: String },
      Mod { #[serde(rename = "mod")] name: String, props: Value },
      /// A tab's terminals as it arranges them (`"active"`: the selected one)
      Context { #[serde(alias = "context")] tab: String, pane: Option<PaneFrame> },
      /// An agent's terminal, full size (`"focused"`: the selected agent).
      Agent { agent: String },
  }
  ```

  Every node may carry `id`, `size` (`{ "px": 240 }` or `{ "weight": 2 }`), `min`, `max`, `hidden`, paint, padding, gaps and dividers, and `resizable` and `movable` flags ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L220-L249)). Panes are dragged by a grip: "Center drop swaps panes; an edge drop places beside it" ([L242-L249](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L242-L249)). Splits change only through commands: `pane.split {direction: "right" | "down", pane?, argv? | mod?, props?}`, `pane.close`, `pane.zoom`, `pane.focus`, `pane.go {direction}`, `pane.swap` ([L559-L576](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L559-L576)).
- **Where the structure is kept: in the core, per machine.** "Each machine keeps its spaces, tabs and splits in its core's `herdr-app` document. Connected screens share that layout and live terminals, not their focus, zoom or attention. Use commands to change structure; there is no `spaces.json`. On simultaneous edits the newest accepted document wins (no merging)" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L93-L104)). The document is `{spaces: [{id, name, folder, tabs: [{id, name, root}]}]}`, and this screen's focus, zoom, settled tabs, recent spaces and seen attention are a private `View` beside it ([`mirror.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/mirror.rs#L9-L61)), written to `view.json` in the app's home ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L85)). The app reads and writes it with `doc.get` and `doc.set` ([`mirror_sync.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/mirror_sync.rs#L76-L94)), the core's opaque, versioned documents: "`doc.set {name, value, version, on?}` writes only if the version matches", up to 1 MiB each, kept in `docs.json`, and "Core never interprets their contents" ([core API](https://github.com/herdrdev/herdr-core/blob/9ce385d9c8abb041dd4437476d770365b3fb5282/schema/README.md?plain=1#L179-L199)).
- **Terminals join by label.** "Herdr labels the ones it starts with `herdr.space=<id>` and `herdr.tab=<id>`. **A terminal with those labels shows up there**, even one you start yourself" with `hc run --keep --label …` ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L139-L152)). Sub-agents "belong to their parent's tab without a pane"; `terminal.peek` opens one over the tab and `terminal.keep` gives it a pane ([L157-L163](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L157-L163)). After a reboot or core crash, "kept panes get fresh shells in their last folders, not their old programs" ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L59-L61)).
- **Layouts arrange the window.** "Each file is one whole window" (`layouts/<name>.json`), switched with `layout.switch`; "Every layout shows the same world; a layout may show less, never a different one" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L93-L96), [L168-L172](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L168-L172)). The default window is a row of a sidebar column (the `spaces` and `agents` mods) and a work column (the `tabs` mod above a `{ "tab": "active" }` block) ([L398-L414](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L398-L414)). A tab block says how each pane is framed, including a `header` mod drawn on every pane ([L347-L370](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L347-L370)); `floating` blocks sit over a node, can be drawers that peek from an edge, and spring to the nearest edge when dropped ([L372-L396](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L372-L396)). Sizes, visibility and other "clicks" live apart from the layout file in `layouts/.state/` ([L213-L218](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L213-L218)). The example layouts include *Threads* ("Every tab becomes a thread in a project inbox", with a composer under the live terminal and Files and Diff on the right) and *Board* (agent cards in Needs you, Working, Done and Idle columns) ([examples](https://github.com/herdrdev/herdr-layout-examples/blob/0ec967640bf854ffb839e9af06c1e0c328bc9815/README.md?plain=1#L17-L27), [Threads recipe](https://github.com/herdrdev/herdr-layout-examples/blob/0ec967640bf854ffb839e9af06c1e0c328bc9815/threads/RECIPE.md?plain=1#L1-L37)); in it a "thread" is a tab of terminals running an agent, not a chat transcript.

### 1.5 Extensibility: layouts and mods

- **Everything is files.** The app home "is **the Herdr app's whole interface, as files** … change a layout, a key or a panel here and the window follows within a second" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L5-L15)): `layouts/<name>.json`, `keys.json`, `settings.json`, `mods/<name>/`, `programs.json` and the app's own state files ([L74-L91](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L74-L91)). A broken edit keeps the last good version and writes `<name>.error`; `ctrl-alt-shift-escape` always resets to the default layout and keys ([L49-L61](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L49-L61)).
- **A mod is a folder** ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L786-L799)):

  ```
  ~/.config/herdr-app/mods/<name>/
    main.js       the mod (required)
    mod.json    where it first appears: { "place": "right" | "left" | "top" | "bottom" | "none", "size": 320 }
    *.js, *.svg   more modules ("./ui.js"), its own icons
  ```

  `mod.json` may also say `"focusable": true` (so `pane.go` can give it the keyboard), a `title`, and an `overlay` (`{"kind": "dialog", "width": 560}`) — for example [`machine-add/mod.json`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/mods/machine-add/mod.json). There is no id, version, dependency list or permission list in it.
- **What a mod is in code.** "`main.js` default-exports a class extending `View`. `init(props, cx)` runs once; `render(cx)` describes the UI and runs again after `cx.notify()` and whenever Herdr's live data changes (spaces, agents, terminals, focus, theme, shared state). Don't poll those"; an optional `async close(cx)` gets at most 250 ms ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L881-L905)). Elements are GPUI's builders in snake case (`div()`, `h_flex()`, `.on_click(...)`), with unstyled controls, a Markdown `TextView` and a code `Editor` from `gpui-base` ([L918-L940](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L918-L940)); animation is declared (`.frames`, `.spin`, `.loop`, `.transition`) because "Every redraw of a mod redraws the whole window" ([L907-L916](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L907-L916)). A copy "stays alive while its block is in the layout, shown or not … Its timers keep running while hidden" ([L809-L814](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L809-L814)). Saving any file reloads every copy in place ([L801-L808](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L801-L808)).
- **The API surface**, generated as `herdr.d.ts` and `gpui-kit.d.ts` beside the guide ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L39-L47), [L942-L1015](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L942-L1015)):
  - live data: `spaces()`, `machines()`, `agents()`, `terminals()`, `panes()`, `focused()`, `layout()`, `theme()`, `settings()`, `keys()`, `commands()`, `layouts()` ([`herdr.d.ts`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/herdr.d.ts#L83-L246));
  - acting: `run(name, args)`, the same commands keys, menus and `herdr-app do` use — "The one way to change anything" ([L81](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/herdr.d.ts#L81), [guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L527-L536));
  - overlays: `openOverlay({ mod, props, layout, kind: "dialog" | "popup" | "window", modal, frame, key, keep, width, height, at })`, `closeOverlay`, `notify` ([`herdr.d.ts`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/herdr.d.ts#L337-L384)); a window overlay can hold a layout with terminal blocks in it ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L977-L986));
  - the machine: `exec(command, args, { cwd, on, timeout })` ("Runs a program with the user's real environment (HOME, PATH, auth)", on another machine through the core with `on`), `hc(args)`, `readTextFile`, `writeTextFile`, `watchFolder`, `knownAgents`, `pickFolder` ([`herdr.d.ts`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/herdr.d.ts#L10-L43));
  - state: `props()`, `shared(key)` and `setShared(key, value)` ("every mod sees it; setting re-renders all"), `nextCommand()` for keys bound to `<mod>:<command>`, `localStorage` per copy ([L386-L407](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/herdr.d.ts#L386-L407), [guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L1009-L1015)).
- **A terminal inside a mod's block.** Mods "show a live terminal inside a block" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L29-L33)), as a layout `{ "terminal": "t7" }` block; they "can't … change how a terminal itself draws text" ([L35-L37](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L35-L37)).
- **Where mods run, and with what permissions.** In the app's process, in one QuickJS VM shared by every mod (the vendored gpui-kit patch speaks of "~40% of the main thread with a mod of many small object-returning functions", [Cargo.toml](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/Cargo.toml#L88-L94); gpui-shell runs filesystem work "off the UI/VM thread", [README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/vendor/gpui-kit/crates/shell/README.md?plain=1#L405-L412)). gpui-shell has a capability model, denied by default and declared in a `gpui-shell.json` with `fs`, `network.hosts`, `network.http`, `storage` and `clipboard` grants ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/vendor/gpui-kit/crates/shell/README.md?plain=1#L298-L330)), but Herdr gives every mod the same broad grant:

  ```rust
  fn capabilities() -> Capabilities {
      Capabilities::new()
          .read_roots([home()])
          .write_roots([app_dir()])
          .execute(ExecuteGrant::Unrestricted)
          .network(NetworkGrant::Unrestricted)
          .storage(true)
          .clipboard_read(true)
          .clipboard_write(true)
  }
  ```

  ([`mods.rs`](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/src/mods.rs#L1140-L1149)). The security page: "A mod is trusted JavaScript running inside Herdr. It can run programs with your environment, fetch URLs and read files. The built-in file API limits writes to the app home, but a mod can run a program to write elsewhere. That is not a security boundary … There is no permission prompt for each program or network request" ([security](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/docs/security.md?plain=1#L3-L10)); "Mods are trusted code, not sandboxed extensions" ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L93)). Mods "can't … read or change other mods' code at run time" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L35-L37)).
- **Installing, sharing and versions.** There is no package manager. Shipped layouts and mods "are replaced whole on every start"; to change one, `layout.clone` or `mod.clone`, which records `cloned_from: {name, version}` (the app's version), and an edited shipped file is moved aside to `<name>-edited` ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L186-L211)). Shared layouts and mods are public GitHub repositories with the topic `herdr-layout` or `herdr-mod`, which herdr.dev lists "within the hour"; each has a `RECIPE.md`, "the brief to build it from scratch", and the guide tells an agent installing one to read every file first, say whether it reaches the network, runs programs or reads files outside its folder, copy it without overwriting, and "If the files don't work on this version … build it from the recipe instead" ([L422-L475](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L422-L475)). herdr.dev counted 215 layouts and 435 mods on 2026-11-07. `herdr-app check <mod folder>` loads a mod and renders it once ([L835-L842](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L835-L842)). The mod API's compatibility is the app's: the `.d.ts` files "are rewritten on every start to match this version" ([L39-L47](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L39-L47)).
- **Written for agents to extend.** "When someone asks for something ('a sidebar of my PRs', 'give ctrl+1 back to the shell', 'make it warmer', 'move the agents list to the right'), you do it by editing these files or writing a mod" ([guide](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/defaults/AGENTS.md?plain=1#L10-L13)); `herdr-app --skill` prints the window manual ([README](https://github.com/herdrdev/herdr-app/blob/adf94cb2c9b6f1cadbb31c51f84114b1aa332f0a/README.md?plain=1#L95-L110)).
- **Herdr 1's plugins, for contrast.** A directory with a `herdr-plugin.toml` (`id`, `name`, `version`, `min_herdr_version`, `platforms`, `[[build]]`, `[[startup]]`, `[[actions]]`, `[[events]]`, `[[panes]]`, `[[link_handlers]]`), whose entries are argv commands; "The entire Herdr CLI is the plugin API", and "Runtime action registration and native non-terminal plugin UI are not part of plugin v1" ([plugins](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/docs/next/website/src/content/docs/plugins.mdx?plain=1#L6-L33), [manifest](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/docs/next/website/src/content/docs/plugins.mdx?plain=1#L55-L104)). A plugin pane is a terminal running a command; Herdr 2's mods replaced that with UI drawn in the window.

### 1.6 Terminal rendering

## 2. T3 Code's clients

T3's server, its Effect RPC over WebSocket, its pairing and its linked environments are in the two earlier notes ([T3 Code and the weave Host §2–4](t3code-and-the-weave-host.md#2-the-server-beside-the-host), [peer environments](t3code-peer-environments.md)). T3 calls a server an *environment* and a repository checkout it works in a *project* ([AGENTS.md](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/AGENTS.md?plain=1#L43-L57)).

### 2.1 Surfaces, and what's shared

- **Three surfaces.** "**Desktop** is the main surface most users install first. It's a full Electron app that bundles the server runner as well. The desktop app can also be used as the host server, allowing remote connections from app.t3.codes or the mobile app"; "**Mobile** is a React Native app for both iOS and Android"; web is both app.t3.codes and the copy `npx t3` serves ([AGENTS.md](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/AGENTS.md?plain=1#L23-L31)). Desktop "wraps web, adds Electron shell/IPC"; mobile is React Native "with separate navigation"; "Shared logic lives in `packages/client-runtime`" ([L70](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/AGENTS.md?plain=1#L70)).
- **The boundary.** "Provider processes, terminals, Git, and project files belong to the server. Shared connection and domain state belongs in `packages/client-runtime`; clients supply platform services and UI" ([overview](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/docs/internals/overview.md?plain=1#L3-L13)). The connection runtime, its supervisor and its projections are described in the [earlier note §4.3](t3code-and-the-weave-host.md#43-how-the-web-client-consumes-the-api).
- **Versions.** Electron 44.10.1 ([desktop package.json](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/desktop/package.json#L25)); web on React with TanStack Router, zustand 5 and `@effect/atom-react` ([web package.json](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/package.json#L28-L93)); mobile on React Native 0.88.0 and Expo 58.0.14 ([mobile package.json](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/mobile/package.json#L83-L123)).

### 2.2 The desktop app

- **The server is a child of Electron.** The desktop app starts the bundled server (`apps/server/dist/bin.mjs`) with Electron's own binary as Node: `executablePath: process.execPath` with `ELECTRON_RUN_AS_NODE: "1"`, its bootstrap on file descriptor 3 ([`DesktopBackendConfiguration.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/desktop/src/backend/DesktopBackendConfiguration.ts#L523-L544)), supervised with restart backoff from 500 ms to 10 s ([`DesktopBackendManager.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/desktop/src/backend/DesktopBackendManager.ts#L35-L36)).
- **The renderer is the web app.** It loads `t3code://` ([`ElectronProtocol.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/desktop/src/electron/ElectronProtocol.ts#L16-L28)), whose handler either proxies a request to the backend's origin or serves a bundled asset ([L160-L244](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/desktop/src/electron/ElectronProtocol.ts#L160-L244)), and talks to the server over the same WebSocket every client uses: "Every client, including the desktop renderer, attaches through the environment connection" ([terminal runtime](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/docs/internals/terminal-runtime.md?plain=1#L3-L6)). Electron IPC carries only the shell's own services: folder pickers, badges, context menus, themes, updates, window state ([`channels.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/desktop/src/ipc/channels.ts#L1-L30)).

### 2.3 The web UI's layout

- **Routes, one thread at a time.** File routes under `_chat`: `/$environmentId/$threadId`, drafts, new, pull requests, usage and some 30 settings pages ([`routes/`](https://github.com/pingdotgg/t3code/tree/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/routes)). The thread view is `ChatView.tsx`, 4,071 lines, beside a sidebar (`AppSidebarLayout.tsx`).
- **Projects grouped across environments.** The sidebar groups projects by repository, by repository and path, or keeps them separate (`SidebarProjectGroupingMode`, default `repository`) ([`settings.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/packages/contracts/src/settings.ts#L81-L87), [`sidebarProjectGrouping.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/sidebarProjectGrouping.ts#L14-L18)). The group key is the repository's identity, so the same repository on two environments is one group, falling back to the physical path ([`projectGrouping.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/packages/client-runtime/src/state/projectGrouping.ts#L103-L150)).
- **A right panel of surfaces, per thread.** The panel holds a list of *surfaces*, one active, of kinds `diff`, `files`, `file`, `preview` (a browser), `device`, `terminal`, `pull-request`, `pull-requests` and `side-chat` (another thread) ([`rightPanelStore.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/rightPanelStore.ts#L15-L79)); its state is `{isOpen, activeSurfaceId, surfaces, maximized?}` keyed by thread ([L91-L98](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/rightPanelStore.ts#L91-L98)), persisted in the browser's storage with zustand's `persist` under `t3code:right-panel-state:v2`, schema version 14 ([L81-L82](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/rightPanelStore.ts#L81-L82)). A terminal surface is a group: `{terminalIds, activeTerminalId, splitDirection?: "horizontal" | "vertical"}` ([L41-L48](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/rightPanelStore.ts#L41-L48)).
- **A terminal drawer, also per thread.** Below the thread, `{terminalOpen, terminalHeight, terminalIds, activeTerminalId, terminalGroups, activeTerminalGroupId}`, persisted under `t3code:terminal-state:v1` ([`terminalUiStateStore.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/terminalUiStateStore.ts#L13-L22)); a group splits one way and holds at most four terminals ([`types.ts`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/types.ts#L35-L42)).
- **No general split tree.** Nothing in `apps/web/src` arranges threads or panels in a recursive tree; the splits are the terminal groups' one level. The layout state lives in each client, not on the server.

### 2.4 The mobile app

- **Layers.** "Each layer below makes one decision, and no layer makes another's": the router's root stack is the layout state; the workspace shell places columns by width class — "_Expanded_: sidebar, content and inspector columns", "_Medium_ (600–720pt wide)", "_Compact_ (under 600pt either way)"; feature screens place content by role; "On iOS 26, the columns are `UISplitViewController` columns with a navigation bar each. On Android and on iPadOS 18–25, the shell draws the same columns in JS" ([mobile layout](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/docs/internals/mobile-layout.md?plain=1#L3-L44)). Selecting a thread and drilling in are separate actions ([mobile navigation](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/docs/internals/mobile-navigation.md?plain=1#L9-L29)).
- **Native modules.** Local Expo modules for the terminal, the composer editor, review diffs, source text, native controls, voice transcription and widgets ([`modules/`](https://github.com/pingdotgg/t3code/tree/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/mobile/modules)); notifications through `expo-notifications` ([package.json](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/mobile/package.json#L107)). "Expo Go is not supported" ([README](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/mobile/README.md?plain=1#L7-L9)).

### 2.5 Terminals

- **The server owns them.** "The environment server owns PTYs, session lifetime, and retained output … Renderer choices stay local to each client and do not change terminal contracts"; history is capped at 5,000 lines and 8 MiB per terminal, client buffers at 512 KiB ([terminal runtime](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/docs/internals/terminal-runtime.md?plain=1#L3-L23)).
- **libghostty-vt everywhere, three renderers.** "Android and web use the same `libghostty-vt` C ABI for terminal behavior. Platform adapters own drawing and input integration, and React stays out of terminal frames. The web adapter shares one WebAssembly instance per browser tab" ([L30-L38](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/docs/internals/terminal-runtime.md?plain=1#L30-L38)), pinned once at [`native/libghostty-vt/VERSION`](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/native/libghostty-vt/VERSION) (`9f62873b`). On the web (and so the desktop), "It is intentionally not an xterm compatibility layer": `core.ts` turns the C ABI into render snapshots, `renderer.ts` "batches backgrounds and style runs into a Canvas 2D frame", `surface.ts` owns input, IME, selection, scrolling and links ([web terminal README](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/web/src/terminal/ghostty/README.md?plain=1#L1-L19)). On iOS the terminal is a native view on a full `GhosttyKit.xcframework` (Ghostty's own renderer) built from a fork with custom I/O, fed with `ghostty_surface_feed_data`; on Android it is libghostty-vt with a Canvas view drawing snapshots from a JNI bridge; to JavaScript the view only emits input and size, and output arrives on the existing RPC stream ([t3-terminal README](https://github.com/pingdotgg/t3code/blob/67fdc53823894f96e5946da80fac5b6c34c0487d/apps/mobile/modules/t3-terminal/README.md?plain=1#L1-L33)).

### 3.3 Capabilities and permissions

- **Capabilities** are JSON, JSON5 or TOML files in `src-tauri/capabilities` that grant permissions to windows and webviews by label, optionally per platform and to remote URLs ([capabilities](https://v2.tauri.app/security/capabilities/)); their fields are `identifier`, `description`, `remote.urls`, `local`, `windows`, `webviews`, `permissions` and `platforms` ([`capability.rs`](https://github.com/tauri-apps/tauri/blob/993038c49185307dfc895ab7657d77ca0d5ed7c7/crates/tauri-utils/src/acl/capability.rs#L128-L204)). On Linux and Android, Tauri can't tell an iframe's requests from its window's ([remote API access](https://v2.tauri.app/security/capabilities/#remote-api-access)). The docs' example ([source](https://github.com/tauri-apps/tauri-docs/blob/5e49cc6e48597060f1618e0b62cb91b071b1b4a9/src/content/docs/security/capabilities.mdx?plain=1#L44-L61)):

  ```json
  { "$schema": "../gen/schemas/desktop-schema.json", "identifier": "main-capability",
    "description": "Capability for the main window", "windows": ["main"],
    "permissions": ["core:path:default", "core:event:default", "core:window:default",
      "core:app:default", "core:resources:default", "core:menu:default",
      "core:tray:default", "core:window:allow-set-title"] }
  ```

- **Permissions** are TOML, named `<plugin>:default` or `<plugin>:<command>`, with scopes and `[[set]]`s ([permissions](https://v2.tauri.app/security/permissions/)):

  ```toml
  [[permission]]
  identifier = "my-identifier"
  description = "This describes the impact and more."
  commands.allow = ["read_file"]
  [[permission.scope.allow]]
  my-scope = "$HOME/*"
  [[permission.scope.deny]]
  my-scope = "$HOME/secret"
  ```

  An app's own commands are allowed everywhere unless `AppManifest::commands` restricts them ([capabilities source](https://github.com/tauri-apps/tauri-docs/blob/5e49cc6e48597060f1618e0b62cb91b071b1b4a9/src/content/docs/security/capabilities.mdx?plain=1#L103-L119)). The model governs which webview may call which Rust command; it is not a runtime for third-party code.

### 3.4 IPC

- **Commands** are `#[tauri::command]` functions called with `invoke`; results are JSON unless a command returns `tauri::ipc::Response` (an `ArrayBuffer`), and a request body can arrive raw as `InvokeBody::Raw` ([calling Rust](https://v2.tauri.app/develop/calling-rust/#returning-array-buffers), [`ipc/mod.rs`](https://github.com/tauri-apps/tauri/blob/993038c49185307dfc895ab7657d77ca0d5ed7c7/crates/tauri/src/ipc/mod.rs#L59-L63)). Async commands run on the async runtime, synchronous ones on the main thread ([source](https://github.com/tauri-apps/tauri-docs/blob/5e49cc6e48597060f1618e0b62cb91b071b1b4a9/src/content/docs/develop/calling-rust.mdx?plain=1#L340-L341)).
- **Events** are "not designed for low latency or high throughput"; payloads are JSON strings delivered by evaluating script in the page ([calling the frontend](https://v2.tauri.app/develop/calling-frontend/#event-system)). With high-frequency events the frontend leaked 1.1 GB after 2 million ([#12724](https://github.com/tauri-apps/tauri/issues/12724), open; fix proposed in [#16446](https://github.com/tauri-apps/tauri/pull/16446), 2026-11-02).
- **Channels** "are designed to be fast and deliver ordered data" and carry Tauri's own download progress, child-process output and WebSocket messages ([channels](https://v2.tauri.app/develop/calling-frontend/#channels)). Each message is one `webview.eval` with an `index` for order; JSON under 8,192 bytes and raw payloads under 1,024 bytes go inline (raw bytes as a JSON number array), and anything larger is queued for the page to fetch back over IPC ([`channel.rs`](https://github.com/tauri-apps/tauri/blob/993038c49185307dfc895ab7657d77ca0d5ed7c7/crates/tauri/src/ipc/channel.rs#L292-L321)). The only figures are the code's own comments: "8192 byte JSON payload runs roughly 2x faster through eval than through fetch on WebView2 v135" and "1024 byte payload runs roughly 30% faster through eval than through fetch on macOS" ([L34-L38](https://github.com/tauri-apps/tauri/blob/993038c49185307dfc895ab7657d77ca0d5ed7c7/crates/tauri/src/ipc/channel.rs#L34-L38)). No throughput benchmark is published; the `bench/` crate is internal CI ([bench](https://github.com/tauri-apps/tauri/blob/993038c49185307dfc895ab7657d77ca0d5ed7c7/bench/README.md?plain=1#L20-L24)).
- **Transport.** Requests go by `fetch` to the `ipc` custom protocol, falling back for good to `window.ipc.postMessage` if that fails; Android never uses the custom protocol, since it can't read request bodies, while iOS does ([`ipc-protocol.js`](https://github.com/tauri-apps/tauri/blob/993038c49185307dfc895ab7657d77ca0d5ed7c7/crates/tauri/scripts/ipc-protocol.js#L19-L84), [wry#1448](https://github.com/tauri-apps/wry/issues/1448), open). WebKitGTK read only the first part of multipart bodies until [wry#1911](https://github.com/tauri-apps/wry/pull/1911) (merged 2026-11-03).
- **Open IPC issues** include removing JSON from IPC ([#7706](https://github.com/tauri-apps/tauri/issues/7706)), raw `ArrayBuffer` events ([#13405](https://github.com/tauri-apps/tauri/issues/13405), PR [#14269](https://github.com/tauri-apps/tauri/pull/14269)), memory blow-up reading large files ([#9190](https://github.com/tauri-apps/tauri/issues/9190), priority high), a full message queue on Windows ([#10546](https://github.com/tauri-apps/tauri/issues/10546)), and `Channel::send` not failing once the page stopped listening ([#10901](https://github.com/tauri-apps/tauri/issues/10901)).

## 5. Fit for weave

This section is judgment. It works from weave at `bab2858f`, with the ADR 0030 work in the working tree on 2026-11-07, and from what the person decided in conversation on 2026-11-07.

### 5.1 What was decided

- **Project → Session → Blocks.**
  - A **Project** is a named thing the person works on, such as Odin. It is registered once, spans Hosts, and has a kind.
    - A git Project comes first. It is known by its remote, so each Host's clones and worktrees match it without being registered again.
    - Later kinds point at a directory on each Host that the person names.
    - A Project is one repository, never a group of several.
  - A **Session** is one directory of a Project on one Host. For a git Project that directory is a worktree: a clone's primary worktree, or a branch worktree in worktrunk's layout ([ADR 0019](../adr/0019-the-host-manages-worktrees-with-git-in-worktrunks-layout.md)). A Session holds a layout of tabs and split panes, as a Rex or tmux session does. It and every Block in it are on its Host.
  - A **Block** is one pane's content, of a type. Threads and terminals come first.
- **Where they live.**
  - Each Session's layout is kept by its Host, so every device sees the same one.
  - Projects are kept by the Dispatcher, the only one of the person's programs that sees every Host ([ADR 0030](../adr/0030-the-dispatcher-is-the-hub-hosts-dial-out-to-it-and-devices-reach-every-host-through-it.md)).
  - Blocks only point at threads and terminals the Host already has, and own nothing.
- **Bots** sit beside Projects, not inside a Session. A Bot's thread moves between Hosts ([ADR 0028](../adr/0028-bots-are-dispatcher-records-whose-work-goes-on-in-ordinary-threads.md), ADR 0030), and a Session is on one Host.
- **"Session" stops meaning thread.** Taking the word for this finishes [ADR 0021](../adr/0021-weave-says-thread-where-acp-says-session.md). The Host protocol's `sessions/*` methods become `threads/*`, and the app's `session-list` and `session-view` become thread. Only `acp-core` keeps ACP's meaning.

### 5.3 The layout

- **Take Herdr's tree, and Rex's floating layer.**
  - Herdr uses one `Node` type for everything: `block`, `row`, `column` and `stack`, with a block holding typed content and `props` (1.4).
  - Rex's `session.view` describes the same split tree in binary form, plus floating layers and a zoomed block, with a `revision` that goes up by one on every change. (Read with `rex api describe session.view` on 2026-11-07.)
  - A Session's layout should be a list of tabs, each holding a tree of `row`, `column` and `stack` nodes whose leaves are Blocks, with floating Blocks over it.
  - A `stack` is what makes one layout work on every device. A phone shows a stack one Block at a time. It can show a whole tab as a stack too, without keeping a layout of its own.
- **Store it as Herdr's core does.** Herdr's core keeps the structure as a versioned, opaque document that every connected screen shares, newest write wins. Focus, zoom and attention stay per screen (1.4).
  - The Host would keep one such document per Session, under a revision, and pass it to clients that watch it.
  - It wouldn't read what's in the document. The Host gains a store of documents, not a model of panes or devices. That keeps to the reason [ADR 0018](../adr/0018-clients-decide-enrichment-above-a-text-floor-and-the-tui-composes-with-its-multiplexer.md) rejected Places: the Host doesn't model devices or decide fidelities.
  - Focus, zoom, and which tab is in front stay on the device, as Herdr keeps them per screen.
- **ADR 0022 needs amending.** It says "the Host keeps no panes or layout", and that tabs and terminals are one to one, so a terminal opened on one device is a tab on every device. A shared layout does that job more generally.
  - Opening a terminal puts a Terminal Block in the Session's document. Every device sees it because they share the document.
  - Closing a Block hides the terminal. Ending it stays an explicit action, as closing a Rex pane already only hides one (ADR 0022's amendment).
  - A terminal or thread with no Block still belongs to its worktree. The Session lists it so it can be placed again.
- **One Session per directory, created on demand.** A Session is known by its Host and its directory. The first thread or terminal opened in a worktree makes its Session, and removing the worktree (refused while a turn or command runs, as now) ends it.

### 5.4 Blocks and extensions

- **A Block type** has a reverse-DNS id, as Rex's block flavors do (`com.superlogical.terminal.shell`), a component that draws it, and `props` that are part of the layout document.
  - The first types are `weave.thread` (props: thread id) and `weave.terminal` (props: terminal id).
  - Next would be `weave.view`, for a tool call's view or a Visual ([ADR 0012](../adr/0012-views-the-host-does-the-mcp-side-and-clients-render.md); the app doesn't render views yet). After it would come a diff of the worktree and a browser.
  - A Block whose type a device doesn't have shows its type and props as text. That is the text floor ADR 0018 asks for.
- **Commands first, as Herdr has them.** Herdr's mods change anything only through `run(command)`, the same commands that keys, menus and the CLI use (1.5).
  - The app should have one command registry before it has extensions. Keys, menus, the command palette and extensions would all act through it.
  - A `weave app` CLI could call it too, which is how an agent at the desk would arrange panes, as agents drive `rex` today.
- **Don't copy Herdr's trust model.** Herdr's mods run in one process with a single grant: read the home folder, run anything, use any network. Its own docs say that is "not a security boundary" (1.5).
  - Weave's app holds device keys to every Host, and it renders agent output under a Content Security Policy that fetches nothing without consent.
  - So third-party Blocks should run as views will: a sandboxed frame talking to the app over a bridge, getting the live data and commands it declared and no more.
  - First-party Block types are built into the app.
  - Herdr's "files in a folder, reloaded when saved" fits for layouts and keys. Herdr's agent guide in that folder, written so agents can extend the app, is worth copying.
- **Tauri adds nothing here.** Its plugins are Rust compiled into the app, and its capabilities gate which webview may call which command (3.2, 3.3). Extensions are the app's own design either way.

### 5.5 Tauri on which devices

- **The Mac: yes.** Tauri gives weave a desktop app whose Rust core links `host-client` and runs on the same tokio as the rest of the workspace (3.7). The core does three things a web view can't:
  - reach the Mac's own Host over its Unix socket, as local clients keep doing under ADR 0030;
  - hold the device key in the Secure Enclave through `host-client`'s macOS code;
  - bridge `terminals.sock` for the terminal stream.

  Electron, T3 Code's choice (2.2), would bring Node and none of those. GPUI, Herdr's choice (1.2), would mean writing the UI again in Rust and leaving the React that the iPad and iPhone share.
- **The iPad and iPhone: not yet.** Today's iOS shell does three things Tauri 2.12 has no documented way to do (3.2, 3.9):
  - draw native terminals under the web view;
  - put a Surface on an external display through its own scene delegate;
  - later, take pushes.

  Tauri has no push plugin, no app or scene delegate to edit, and Swift plugins only on iOS. It also has open keyboard and safe-area issues on iPad, and Xcode 27 isn't supported.
  - Moving the iPad and iPhone now would lose the native terminal, which ADR 0022 chose after testing it on an iPad, and the Surface (WVE-183).
  - T3 Code, which also renders libghostty-vt with WASM on the web, chose GhosttyKit's own native renderer on iOS (2.5).
- **So: one React codebase, two shells.**
  - Tauri on the Mac, Capacitor on the iPad and iPhone, both on the same Project, Session and Block UI.
  - The shells sit behind a platform seam beside the `AppController` seam that already exists. The seam would cover device keys, terminals, the local Host and windows.
  - Revisit Tauri on iOS when it can host a native view and take pushes. The seam makes that a change of shell, not of app.
  - If the person would rather have one shell now, Tauri on iOS works for threads but not yet for native terminals or the Surface.
- **The Thread Block's data stays in TypeScript.** The Host store and the transcript are tested and shared with iOS.
  - On the Mac, the Rust core is the transport: it relays the Host socket and the Dispatcher's WebSocket to the page through a channel.
  - Thread traffic is JSON well under the 8 KiB Tauri sends inline (3.4).
  - A second client implementation in Rust would split the app in two.

### 5.6 Terminals in the Mac app

- **Bytes don't go through Tauri's IPC.**
  - Channels send raw bytes under 1 KiB as a JSON array of numbers, and fetch anything larger back with a second call (3.4).
  - Events are documented as unfit for throughput, and leaked memory at high rates.
  - The iOS shell already keeps terminal bytes off Capacitor's bridge for the same reason (ADR 0022: 5 to 10 MiB/s through base64).
- **The page opens a WebSocket to each terminal itself.**
  - For a remote Host, that is the terminal stream through the Dispatcher.
  - For the Mac's own Host, the Rust core serves `terminals.sock` to the page as a loopback WebSocket with a per-launch token.
- **libghostty-vt in WASM, drawn on a canvas.** T3 Code does this on web and desktop (2.5), and `ghostty-web` exists for Tauri apps (3.8).
  - This revisits ADR 0022's choice of a native renderer, but only for the desktop. On an iPad the reasons were the hardware and software keyboards, Split View and suspending, which matter less on a Mac.
  - It shares the holder's Ghostty pin, and its snapshot codec follows the same version rule.
  - If performance falls short, the other way is `WeaveTerminalRenderer.mm`, which already builds for macOS (`bun run native:test`), as an `NSView` beside the web view. Tauri doesn't document that (3.2).

### 5.7 Projects

- **The record** is in the Dispatcher: an id, a name, a kind and, for a git Project, its remote.
  - The Dispatcher asks each Host for its repositories, which the Host knows through its worktree management (ADR 0019), and matches them by normalised remote. T3 Code groups projects across machines by repository identity in the same way (2.3).
  - A Project with no clone on a Host can offer to clone it there. That is a new Host request, and it fits under ADR 0019.
- **The sidebar:** Projects, each with its Sessions labelled by Host and branch, and each Session with its threads and terminals as Herdr's spaces nest worktrees under their repository (1.4). Bots sit above the Projects.
- **Without the Dispatcher,** the Mac's app still reaches its own Host and groups its Sessions by repository, as the app's sidebar does today (WVE-162). Projects come back when the Dispatcher does.
- **Directories outside a repository** belong to no git Project. A plain-directory Project covers them once that kind exists. Until then a Host's other directories go under the Host itself.

### 5.8 Bots

- A Bot opens in a Thread Block that follows the Bot: its current thread, then the successor, even on another Host (ADR 0028).
  - It can't sit in a Session's layout, which is on one Host.
  - So it opens in a space of its own: a Bots tab or window, as ADR 0028 planned a "Bots" session in Rex.
- Bots wait on WVE-118. The sidebar can list them, with their states (needs the person, working, unread, idle), as soon as the Dispatcher serves them. Herdr's agent sidebar, built from OSC 7501 states (1.3), is the same idea across threads.

### 5.9 What dropping Rex retires

Keep these until the Mac app is where the person works:

- the `[rex] open_threads` client in `weave daemon` and `[rex]` in the config (ADR 0025);
- the TUI's terminal panes as Rex panes (ADR 0022's amendment), though `weave terminal attach` stays for any terminal;
- ADR 0018's Rex-specific browser panes, though the TUI composing with *a* multiplexer through OSC 7 and OSC 7501 stays;
- the Rex "Bots" session in ADR 0028.

Each needs a superseding ADR, not a silent deletion. The holder's interface keeps Rex's block concepts whatever happens to Rex.

### 5.10 Order of work

4. **Dispatcher:** Projects and repository matching. Session documents reach devices through ADR 0030's pass-through without the Dispatcher reading them.

6. **The Mac shell in Tauri:** the Rust core for the local socket, the Dispatcher, keys and terminals; a WASM terminal.

### 5.11 Decided after this note, on 2026-11-07

The person agreed with sections 5.1 to 5.10 and settled the questions this section had left open:

- **The iPad and iPhone stay on Capacitor.** Only the Mac moves to Tauri.
- **Any mixture of Blocks.**
  - A Session's layout holds Blocks of any type anywhere in its tree, built-in or extension, sandboxed or trusted.
  - Extension Blocks run sandboxed by default. A trusted local Block, Herdr-style, runs only when the person turns it on for that Block type on that device.
  - Every Block in a Session points at something on the Session's Host. A thread in another directory on that Host may sit in it.
- **Bots don't belong to Projects, for now.**
  - A Bot's agent sees and works with any thread through the Host tools: on its own Host under [ADR 0023](../adr/0023-agents-act-on-any-thread-and-the-hosts-reports-tell-nobody-back.md), and on the person's other Hosts through the Dispatcher under [ADR 0029](../adr/0029-agents-reach-the-persons-other-hosts-through-the-dispatcher.md).
- **The Mac's terminals start as libghostty-vt in WASM on a canvas.** If the iPad's native terminal does clearly better on a flood of output or on typing latency, the Mac switches to the native renderer in an `NSView`.
- **What stays on each device:** focus, zoom, the tab in front, scroll positions, and how a phone presents the layout (each tab as a stack). None of it is written to the Session's document, so a phone hides nothing from the others.

The work is filed in Linear under one parent issue, with WVE-189 and WVE-192 moved under it. That issue's description records these decisions.
