## In brief

- **What agents write.** Everyday output is GFM: tables, fenced code with a language, inline code for paths. Math arrives in four delimiter forms, `$…$`, `$$…$$`, `\(…\)` and `\[…\]`, and CommonMark strips the backslash from the last two before any math renderer sees them (1, 18.1). Mermaid is the one diagram language clients converge on. Every GUI client surveyed renders it except Goose, and in the terminal Codex and opencode do (2, 15). Graphviz, PlantUML, maps and STL models are niche.
- **The app** renders through Streamdown without any of its plugins. Agent Markdown images load as soon as a message shows, which breaks weave's no-fetch rule today, independent of this issue (3). Mermaid's `strict` level still loads images and lets diagram links open in Safari without confirmation (5). So the recommendation is the app's own Mermaid and math plugins over Streamdown's plugin types, `@streamdown/code` for highlighting, and a Content Security Policy as the backstop (13).
- **The TUI.** Codex, which the TUI follows, has drawn Mermaid as Unicode text since September 2026: a bounded crate covering subsets of five diagram families, falling back to the source. It turns TeX into Unicode for all four delimiters (15.1). Adapting both works in both screen modes and in every terminal. Diagrams as images would work only in the fullscreen transcript on Ghostty, kitty and cmux (17, 20). pulldown-cmark 0.10.3 lacks a fix for quadratic parsing of crafted HTML comments, and 0.13.5 also brings GFM alerts (19, 22).
- **Neither client needs a Host protocol change.** Each decides what it renders above the text floor (ADR 0018), and every enrichment falls back to the source.

### 1.2 What this means for weave's agents

The agents weave runs are coding agents told that a terminal renders them: Gemini CLI says so outright, and Codex's instructions are written for "the CLI" and its renderer ([default.md](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/protocol/src/prompts/base_instructions/default.md?plain=1#L147)). Their everyday output is therefore GFM: headings, bullets, tables, fenced code with a language, inline code for paths. Math and diagrams appear when the person asks for them or the task invites them (judgment). When math does appear, it arrives in at least four delimiter forms, `$…$`, `$$…$$`, `\(…\)` and `\[…\]`, plus GitHub's ```` ```math ```` fence.

### 2.3 What the survey shows

- Mermaid is the shared diagram format: every client here except Goose renders it, all on the device. They isolate it differently: GitHub in an iframe from a separate service, VS Code in a web view whose CSP allows only `data:` images, Zed with no web engine at all, LibreChat as an `<img>` of a sanitized SVG, Open WebUI with its own sanitizer over `loose` output, and Streamdown inline through `innerHTML` (section 5). Both chat applications that render Mermaid with mermaid.js turn HTML labels off, and Open WebUI locks that setting.
- The Mermaid renderers in the open-source clients render only a closed fence (Zed, VS Code, Open WebUI) or wait and keep the last good diagram (LibreChat). None of them shows a parse error while the diagram is still arriving; Streamdown 2.7.1 can (4.3).
- Math delimiters split the field. Open WebUI, LibreChat and Cursor accept `\(…\)` and `\[…\]`; Goose, VS Code and Streamdown accept only dollars; Zed renders no math. None of the clients rewrites backslash delimiters to dollars; those that accept them parse them. Single-dollar inline math is off in Goose, Streamdown and Cursor because of currency; VS Code and LibreChat keep it behind currency heuristics.
- Remote images in agent Markdown load automatically in Zed, Goose, Open WebUI and LibreChat. Only VS Code blocks them. Only VS Code (for untrusted domains) and Goose (for unusual schemes) ask before opening a link. Weave's rules, no fetch and no link without consent, are stricter than any client surveyed.

### 4.3 Streaming

- **Unclosed math.** `remend` repairs the tail of a streaming message; with an odd number of `$$` it appends the closing `$$` ([katex-handler.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/remend/src/katex-handler.ts#L33-L60)), and Streamdown keeps a block with an unclosed `$$` together when it splits the message ([parse-blocks.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/parse-blocks.tsx#L226-L229)). A half-written formula therefore renders as far as it goes. Where the partial TeX is invalid, rehype-katex retries with `throwOnError: false` and `strict: 'ignore'`, which draws the bad part in `errorColor` ([rehype-katex](https://github.com/remarkjs/remark-math/blob/88a9497e1ede93b958237c85edbf5651faeca7af/packages/rehype-katex/lib/index.js#L87-L125)).
- **Half-written diagrams.** Each diagram keeps one render in flight and renders only the latest chart when it settles. While the fence streams it yields for as long as the last layout took ([mermaid/index.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/index.tsx#L95-L214)). In 2.7.1, a partial chart that fails to parse shows the red error box whenever no earlier prefix rendered (L156-L169, L241-L281). On `main`, [#668](https://github.com/vercel/streamdown/blob/97c1f87ff6b231edc6a752f8510a4d6f320bf712/packages/streamdown/lib/mermaid/index.tsx#L160-L175) shows the loader until the fence closes and only then reports an error; it is not yet released. Both paths depend on `isAnimating` (section 3).
- **Streaming code.** A streaming block re-tokenizes only the lines completed since the last update and is not cached; finished blocks go into a bounded LRU cache ([index.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown-code/index.ts#L111-L273)). A language name cut off mid-stream falls back to plain text (L351-L357).

### 4.4 Errors

With `suppressErrorRendering`, Mermaid throws instead of drawing its own error diagram ([mermaidAPI.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/mermaidAPI.ts#L555-L566)). Streamdown keeps the last valid SVG, and otherwise shows "Mermaid Error: …" with the source in a `<details>`, styled `bg-red-50` and `text-red-700`, light colours meant for a light page. A `mermaid.errorComponent` receiving `chart`, `error` and `retry` replaces it ([mermaid/index.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/index.tsx#L241-L281)). Invalid TeX shows its source in a `katex-error` span (rehype-katex, above). An unknown code language falls back to plain text.

### 4.5 Controls

`controls` configures tables (copy, CSV separator, download, fullscreen), code (copy, download), Mermaid (download as SVG, PNG or `.mmd`, copy, fullscreen, pan-zoom buttons) and images (download) ([index.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/index.tsx#L208-L235)). Inline, a diagram fits to its width; a pointer drag pans it, the wheel zooms it, and buttons zoom and reset. The diagram element sets `touch-action: none` and captures the pointer ([pan-zoom.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/pan-zoom.tsx#L256-L306) and [L450-L466](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/pan-zoom.tsx#L450-L466)). `panZoom: false` only hides the buttons ([components.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/components.tsx#L986-L990)); dragging still pans. There is no pinch gesture. Fullscreen portals a fixed overlay into `document.body` or the `portal` prop's target ([fullscreen-button.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/fullscreen-button.tsx#L128-L134)). PNG export draws the SVG into a canvas ([mermaid/utils.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/utils.ts#L142-L180)), and every download goes through an `<a download>` on a blob URL ([utils.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/utils.ts#L35-L47)).

## 5. Mermaid and weave's rules

### 5.1 What `strict` does

Mermaid documents four levels: `strict` (the default: "HTML tags in the text are encoded and click functionality is disabled"), `antiscript`, `loose`, and `sandbox`, which renders in a sandboxed iframe ([config.schema.yaml](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/schemas/config.schema.yaml#L230-L246)). The code does less encoding than that sentence says:

- **Labels.** With HTML labels, which are on unless configured off ([config.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/config.ts#L246-L252)), `strict`, `antiscript` and `sandbox` all pass label text through DOMPurify with its default allowlist, `style` forbidden; entity encoding applies only to a level outside the four ([common.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/diagrams/common/common.ts#L67-L94)). Tags DOMPurify allows by default, `<img src>` and `<a href>` among them, survive in a `strict` label.
- **The whole SVG.** For every level but `loose`, the serialized SVG goes through DOMPurify once more, with `foreignobject` added ([mermaidAPI.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/mermaidAPI.ts#L624-L633)). Streamdown then sets that string as `innerHTML` and sanitizes nothing further ([mermaid/index.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/mermaid/index.tsx#L308-L315)).
- **Rendering happens in the page.** Outside `sandbox`, Mermaid lays the diagram out in a temporary element appended to `document.body` ([mermaidAPI.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/mermaidAPI.ts#L537-L545)), so anything the diagram references loads during layout, before any sanitizing. Flowchart image shapes (`A@{ img: "https://…" }`) are loaded on purpose, at every level: `new Image()`, `img.src = node.img`, `await img.decode()` ([imageSquare.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/rendering-util/rendering-elements/shapes/imageSquare.ts#L14-L16)).
- **Links.** `click A "https://…"` passes the URL through `@braintree/sanitize-url` unless the level is `loose` ([utils.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/utils.ts#L247-L259)), then wraps the node in `<a xlink:href>` ([nodes.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/rendering-util/rendering-elements/nodes.ts#L36-L48)). Only the JavaScript-callback form of `click` is limited to `loose` ([flowDb.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/diagrams/flowchart/flowDb.ts#L498-L502)). Class, Gantt and sequence diagrams emit links too. In the app, tapping such a link navigates the web view's main frame, and Capacitor hands any URL outside the app to `UIApplication.shared.open` and cancels the navigation ([WebViewDelegationHandler.swift](https://github.com/ionic-team/capacitor/blob/06e3e1984337f836a4c28b2afc92faa977dea315/ios/Capacitor/Capacitor/WebViewDelegationHandler.swift#L101-L121)): the link opens in Safari, or in whatever app owns its scheme, with no confirmation.
- **Directives and front matter.** Both `%%{init: …}%%` and front-matter `config:` become directives ([mermaidAPI.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/mermaidAPI.ts#L75); [config.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/config.ts#L173-L186)). Unknown keys are dropped; `themeCSS`, `fontFamily` and `altFontFamily` are checked only for balanced braces; `themeVariables` are limited to a safe character set ([sanitizeDirective.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/utils/sanitizeDirective.ts#L80-L98)). Keys listed in `secure` cannot be set by a diagram at all ([config.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/config.ts#L131-L143)). The default list is `secure`, `securityLevel`, `startOnLoad`, `maxTextSize` (50 000 characters), `suppressErrorRendering` and `maxEdges` (500) ([config.schema.yaml](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/schemas/config.schema.yaml#L107-L116) and [L258-L271](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/schemas/config.schema.yaml#L258-L271)). A diagram can therefore turn HTML labels back on, change the theme, or add CSS whose `url()` loads a remote resource (the last is inference from the brace-only check).

### 5.2 Against the rules

| Rule | With Streamdown's defaults | What closes the gap |
| --- | --- | --- |
| No script | Met: `strict` plus two DOMPurify passes; no callbacks | Keep `strict` |
| No remote fetch without consent | Not met: image shapes, `<img>` in HTML labels, and `url()` in diagram CSS can all load | A Content Security Policy for the app; HTML labels off and locked; theme keys locked |
| No link opened without consent | Not met: `<a xlink:href>` in the SVG opens through Capacitor without the dialog | Rewrite the SVG's links before it reaches the DOM, or catch clicks on the diagram and route them to the confirmation |

LibreChat's approach closes all three differently: it shows the sanitized SVG as an `<img>` from a blob URL ([useSvgProcessing.ts](https://github.com/danny-avila/LibreChat/blob/a378657583567310c841d652b0f6b00c83e2bd6b/client/src/components/Messages/Content/Mermaid/useSvgProcessing.ts#L83-L90)). An SVG shown as an image runs no script, follows no links and loads nothing external (inference from how browsers treat SVG images). Mermaid's own layout pass still runs in the page, though, so image shapes would still load there.

## 6. KaTeX and weave's rules

- **`trust`.** KaTeX's default is `false`: `\href`, `\url`, `\includegraphics`, `\htmlClass`, `\htmlId`, `\htmlStyle` and `\htmlData` render as unsupported commands in `errorColor` ([options.md](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/docs/options.md?plain=1#L50-L60); [href.ts](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/src/functions/href.ts#L18-L27); [includegraphics.ts](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/src/functions/includegraphics.ts#L87); [html.ts](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/src/functions/html.ts#L76); [Settings.ts](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/src/Settings.ts#L464-L476)). `@streamdown/math` passes only `errorColor`, so trust stays off. With trust off, KaTeX's output has no links and loads nothing but its own fonts, so it never meets the link confirmation.
- **Limits.** `maxExpand` defaults to 1000 macro expansions, but `maxSize` defaults to `Infinity`, so `\rule{500em}{500em}` draws a box of that size ([options.md](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/docs/options.md?plain=1#L28-L29)). `@streamdown/math` cannot set it. rehype-katex accepts every KaTeX option except `displayMode` and `throwOnError` ([rehype-katex](https://github.com/remarkjs/remark-math/blob/88a9497e1ede93b958237c85edbf5651faeca7af/packages/rehype-katex/lib/index.js#L8)), so a math plugin of the app's own can.
- **Sanitizing.** KaTeX says its HTML "*should* be safe from `<script>`" but advises sanitizing it with "a rather generous whitelist" ([security.md](https://github.com/KaTeX/KaTeX/blob/878a61be7743a8ec4ee725b0b5efa810b5167c79/docs/security.md?plain=1#L5-L16)). Streamdown runs it after sanitize (4.1).
- **Delimiters.** remark-math parses dollars only; its `singleDollarTextMath` option exists because single dollars "often interfere with 'normal' dollars in text" ([readme](https://github.com/remarkjs/remark-math/blob/88a9497e1ede93b958237c85edbf5651faeca7af/packages/remark-math/readme.md?plain=1#L155-L159)). Streamdown's docs make the same choice "to avoid conflicts with currency symbols" ([math.mdx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/apps/website/content/docs/plugins/math.mdx?plain=1#L76)). Accepting OpenAI's `\(…\)` and `\[…\]` needs a micromark extension that parses them, as LibreChat's `micromark-extension-llm-math` does, or a pass that rewrites them outside code before parsing.

## 8. iOS and Capacitor

### 8.1 Offline

KaTeX's CSS names its fonts by relative URL (`url(fonts/KaTeX_AMS-Regular.woff2)`, then `.woff` and `.ttf`), so Vite copies all 60 font files into the build, about 1.08 MB; WebKit loads only the woff2 files (inference from the `src` order and WebKit's woff2 support). Neither Shiki nor Mermaid loads anything from a CDN: Shiki's grammars and themes are modules in the bundle, and Mermaid's icon packs (`icon:` shapes, architecture diagrams) only exist once an integrator registers them with `registerIconPacks`; the documented example's loader fetches from unpkg, the alternative imports a bundled package ([icons.md](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/docs/config/icons.md?plain=1#L16-L39)), so an app that registers packs should bundle them. All three work offline.

### 8.2 WKWebView

The app targets iOS 15 ([project.pbxproj](../../app/ios/App/App.xcodeproj/project.pbxproj), L245). Shiki's JavaScript engine uses the RegExp `v` flag where it exists (ES2024) and otherwise falls back to `u`, which "results in a few less grammars being supported" ([regex-engines.md](https://github.com/shikijs/shiki/blob/f7d0167873fd676fe4e190bc9b53832fba9ee01d/docs/guide/regex-engines.md?plain=1#L76-L84)); Safari and iOS Safari gained it in 17 ([browser-compat-data](https://github.com/mdn/browser-compat-data/blob/56e6f1217a54dfe0d25df29d0f67c6a26cdc3901/javascript/builtins/RegExp.json#L1677)), so iOS 15 and 16 get the reduced set. Streamdown polyfills `requestIdleCallback` ([use-deferred-render.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/hooks/use-deferred-render.ts#L74-L98)). Nothing found in Mermaid or KaTeX needs more than WebKit offers; device testing has to confirm it.

### 8.3 Many diagrams in a long transcript

Mermaid lays out on the main thread and queues every `render` call to run one after another ([mermaid.ts](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/mermaid.ts#L321-L338) and [L381](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/packages/mermaid/src/mermaid.ts#L381)). Streamdown renders a diagram only once it is within 300 px of the viewport ([use-deferred-render.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/hooks/use-deferred-render.ts#L12) and [L192](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/hooks/use-deferred-render.ts#L192)), then keeps the SVG, so scrolling back through a long thread lays each diagram out once. Code blocks use `content-visibility: auto` ([container.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/code-block/container.tsx#L28-L30)). One cost to know: a message with a footnote is parsed as a single block ([parse-blocks.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/parse-blocks.tsx#L337)), losing the per-block memoization that keeps streaming cheap.

### 8.4 Theme

The app is dark-only: it adds `dark` to `<html>` ([main.tsx](../../app/src/main.tsx), L7), defines Tailwind's `dark` variant on that class, and keeps Zed's Catppuccin Mocha roles as hex values ([styles.css](../../app/src/styles.css), L71-L91). Shiki's two themes switch through `dark:` classes on each token ([body.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/code-block/body.tsx#L118-L190)), so the app would show the second theme, and `catppuccin-mocha` is one of Shiki's 65. Mermaid's theming "will only recognize hex colors and not color names" ([theming.md](https://github.com/mermaid-js/mermaid/blob/dcb694ddb58dc5ad3502e7e903cac05fd812eac3/docs/config/theming.md?plain=1#L136)), so CSS variables cannot be passed through; the app would read its `--zed-*` values with `getComputedStyle` once and pass them as `themeVariables` with `theme: "base"`. Streamdown's Mermaid frame uses the app's tokens (`bg-sidebar`, `border-border`), but its error box does not (4.4).

### 8.5 Small screens

Page zoom is off (`user-scalable=no` in [index.html](../../app/index.html), L7; `zoomEnabled: false` in [capacitor.config.ts](../../app/capacitor.config.ts), L14), so a wide diagram can only be zoomed by Streamdown's buttons or in fullscreen. An inline diagram fits to the column's width, and because its element sets `touch-action: none` (4.5), a vertical swipe that starts on a diagram pans the diagram instead of scrolling the transcript (inference from the code; to confirm on a device). Downloads use `<a download>` on a blob URL; Capacitor's iOS web view delegate implements no download handling, and its navigation policy sends URLs outside the app to `UIApplication.shared.open` ([WebViewDelegationHandler.swift](https://github.com/ionic-team/capacitor/blob/06e3e1984337f836a4c28b2afc92faa977dea315/ios/Capacitor/Capacitor/WebViewDelegationHandler.swift#L101-L121)). Downloading a diagram, a code block or a table probably does nothing in the app (inference; to confirm on a device). Copy uses `navigator.clipboard.writeText`.

## 9. Code highlighting

`@streamdown/code` is Shiki 4 with the JavaScript regex engine, 242 bundled languages loaded one at a time, and a pair of themes (4.2). Languages resolve through Shiki's aliases, and unknown or truncated names fall back to plain text ([index.ts](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown-code/index.ts#L80-L105) and [L351-L357](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown-code/index.ts#L351-L357)). The plugin imports Shiki's full bundle, so every grammar becomes a chunk in the app, about 8.6 MB before minification; only the grammars a transcript uses are parsed. The plugin offers no way to limit the set; a highlighter of the app's own built on Shiki's fine-grained bundle could (judgment). The Oniguruma WASM chunk would also land in the build without being loaded (inference from `bundle-full.mjs`'s dynamic import).

## 10. Alerts, footnotes and inline HTML

- **Alerts.** Not rendered (section 3). The syntax is a blockquote whose first line is `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` ([GitHub docs](https://github.com/github/docs/blob/02c25d16369fe27f9bdb28d1201f6b452f0d21dd/content/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax.md?plain=1#L428-L445)), so a remark plugin can turn it into a styled blockquote with no HTML involved. `remark-github-blockquote-alert` 2.1.0 does this with one dependency, `unist-util-visit` (npm metadata); a plugin of the app's own would be a few dozen lines (judgment).
- **Footnotes.** remark-gfm renders them, but their links pass through link safety (section 3). Fragment links need an `a` component that scrolls to the target instead of confirming.
- **Inline HTML.** Streamdown's `allowedTags` extends its sanitize schema only when `rehypePlugins` is Streamdown's own default array ([index.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/index.tsx#L986-L1009)); the app passes its own array, so the prop does nothing for it. An allowlist such as `br`, `kbd`, `sup`, `sub`, `ins`, `del`, `details` and `summary` takes four steps: replace `htmlAsText` with a remark step that keeps an `html` node only when every tag in it is on the list and carries no attributes (perhaps `open` on `details`) and turns every other node into text as now; put `rehype-raw` back so the kept tags become elements; give `rehype-sanitize` a schema cut down to Markdown's own elements and the list, without `img`, `picture` or `source`; keep `harden`. Streamdown already keeps an HTML block open across blank lines while it splits a message, so a `<details>` around Markdown stays one block ([parse-blocks.tsx](https://github.com/vercel/streamdown/blob/4e8cf96bc7a57bb08b4763b9c8160ab75b094a52/packages/streamdown/lib/parse-blocks.tsx#L171-L215)). The remark step keeps today's behaviour, raw HTML shown as the text it is, for everything off the list.

## 11. Where Markdown ends and views begin

An HTML or SVG fence the client runs is an artifact: claude.ai, ChatGPT, Open WebUI and LibreChat all run them in a frame or a separate origin (section 2). In weave that belongs to views and WVE-96, not to Markdown rendering. The line drawn here: the app renders Markdown into its own DOM only where the result is inert, meaning no script, no fetch and no navigation, and shows any fence it does not render as code. Mermaid fits inside the line once section 5's gaps are closed. An `svg` fence does not fit: a client would have to sanitize arbitrary SVG, which no client in this survey does inline (Open WebUI and LibreChat send SVG to their artifact frames).

## 12. Open questions

- Should agents learn what the app renders? Agents are told they render in a terminal (1.1); Zed tells its own agent what its panel renders, down to preferring tall diagrams (1.1); and claude-agent-acp accepts a client system prompt to append ([client-system-prompt.ts](https://github.com/agentclientprotocol/claude-agent-acp/blob/739dde3ae5bb848bdb90e2c9150e2cc4687d480c/src/client-system-prompt.ts)). But one thread can have the TUI and the app attached, and ADR 0018 keeps the Host from tailoring output to a client. This note assumes agents keep writing for the text floor.
- Does `touch-action: none` on inline diagrams break transcript scrolling on an iPhone, and does a CSS override (`pan-y`) fix it without breaking pan? Needs a device.
- Do downloads (code, table, diagram) do anything in the Capacitor shell? Needs a device; if not, the controls should go or become a share sheet.
- With HTML labels off, do the diagram types agents use (flowchart, sequence, state, class, ER, Gantt) look right? Open WebUI and LibreChat both ship that way.
- Should single-dollar math stay off? Claude writes `$x$` (inference, 1.1), which would then stay as text; LibreChat shows that a currency-aware parser is possible.
- Should the app override KaTeX to 0.18.2 or later for a low-severity advisory, at the cost of departing from what rehype-katex declares?

## 13. Fit for the app

### 13.1 Fix the floor first

These hold whether or not any plugin is added, and the first is a live gap.

1. **Stop remote images.** The bluntest fix is `harden` with `allowedImagePrefixes: []`, which renders "[Image blocked: alt]" in place of each image (checked with the render script). Better is a remark step that turns each Markdown image into a link labelled with its alt text, so it goes through the existing confirmation and opens in the browser. `data:` images are lost either way, but they already are: the default sanitize schema allows only `http` and `https` in `src` ([schema.js](https://github.com/syntax-tree/hast-util-sanitize/blob/7f30d9e6261583efc544ff6a93ba54ca6e53e1b5/lib/schema.js#L141-L146)), and the render check showed a `data:` image blocked under today's configuration. The app then never fetches an image itself, which also suits "never fetch URLs from the client". Prefer this to click-to-load, which would make the app the fetcher and keep a CSP from forbidding remote images outright.
2. **Add a Content Security Policy** to `index.html` as the backstop: `default-src 'self'`, `img-src 'self' data: blob:`, `media-src 'self' data:` (the app plays ACP audio blocks from `data:` URLs, [content-block-view.tsx](../../app/src/chat/content-block-view.tsx), L145), `font-src 'self'`, `style-src 'self' 'unsafe-inline'` (Mermaid's SVG carries a `<style>`, KaTeX inline styles), `script-src 'self'`, and `connect-src 'self' ws: wss:` for the Hosts' WebSockets, whose addresses vary. Whether every library runs without `'unsafe-eval'` has to be checked in a build. It stops every remote load sections 3 and 5 found, including the ones Mermaid makes during layout, which no sanitizer can reach. WVE-96's view frames will need their own `frame-src` when they arrive. This is the one change that makes "no remote fetch" hold by construction instead of by auditing each renderer (judgment).
3. **Footnote links scroll** instead of asking to be opened.
4. **Pass `isAnimating`** for the message that is still streaming, so Streamdown's streaming paths for Mermaid and code run.

### 13.3 Leave out

- HTML, SVG, React or any other fence meant to run or be previewed: views, WVE-96 (section 11).
- Graphviz, PlantUML, Vega, GeoJSON, TopoJSON, STL: niche (1.3). PlantUML usually means a rendering server, and maps mean tile servers, both remote fetches. A `renderers` entry can add any of them later without touching the rest.
- CSV or JSON shown as tables: agents write GFM tables.
- `@streamdown/cjk` until CJK text shows up in practice.
- Mermaid's `loose` and `sandbox` levels, KaTeX's `trust`, and Streamdown's `allowedTags`.

### 13.4 Trade-offs

Owning the math and diagram plugins instead of installing `@streamdown/math` and `@streamdown/mermaid` costs two small modules, each a few dozen lines against Streamdown's plugin types, and in return gives lazy loading, KaTeX limits, the backslash delimiters, locked Mermaid settings and SVG post-processing, none of which the published plugins expose. Turning HTML labels off trades some label styling for no HTML inside diagrams and a PNG export free of `foreignObject` (judgment). The CSP will need care as views arrive, but it is the only defence that covers renderers the app does not control line by line. Streamdown's Mermaid component stays in use, so its deferral, streaming and fullscreen come for free; the price is its touch handling, which a device test may show needs an override.

**Recommendation.** Do 13.1 now, as its own change; the image gap does not wait for WVE-122. Then add code highlighting and math, which are low-risk and cover what agents write most often after tables and code. Then Mermaid with the configuration above, tested on an iPhone and an iPad for scrolling, fullscreen and theme. Alerts and the HTML allowlist can ride along with either step.

## 18. Math

### 18.1 Which delimiters

No first-party source says which delimiters models emit. The evidence is what renderers accept:

- GitHub documents `$…$`, ``$`…`$``, `$$…$$` and ```` ```math ```` fences, rendered with MathJax, and not `\(…\)` or `\[…\]` ([GitHub Docs, writing mathematical expressions](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)).
- Codex accepts `$`, `\(`, `$$` and `\[` (15.1), and Claude Code's VS Code extension the same four (15.2).
- Gemini CLI accepts `$` and `$$`; opencode accepts fenced `latex` and `math` blocks.

Inference: two harnesses built by model vendors both added `\(` and `\[`, which suggests their models write them. Those are the two forms CommonMark destroys, since `\(` parses as an escaped `(` ([CommonMark 0.31.2 §2.4](https://spec.commonmark.org/0.31.2/#backslash-escapes)). Whatever weave does, it has to see the source before pulldown-cmark does, as Codex does.

### 18.2 pulldown-cmark's math extension

`ENABLE_MATH` (0.11.0 and later) emits `Event::InlineMath` and `Event::DisplayMath` for `$` and `$$` only ([v0.13.5 `lib.rs` L545-L559](https://github.com/pulldown-cmark/pulldown-cmark/blob/48a2767b5b8ab0a4893e80d942e510065889fc6b/pulldown-cmark/src/lib.rs#L545-L559), [L716-L718](https://github.com/pulldown-cmark/pulldown-cmark/blob/48a2767b5b8ab0a4893e80d942e510065889fc6b/pulldown-cmark/src/lib.rs#L716-L718)). Its syntax follows commonmark-hs ([`specs/math.txt` L1-L6](https://github.com/pulldown-cmark/pulldown-cmark/blob/48a2767b5b8ab0a4893e80d942e510065889fc6b/pulldown-cmark/specs/math.txt#L1-L6)):

- A lone `$` stays text ([L80-L90](https://github.com/pulldown-cmark/pulldown-cmark/blob/48a2767b5b8ab0a4893e80d942e510065889fc6b/pulldown-cmark/specs/math.txt#L80-L90)).
- Inline math cannot start or end with whitespace ([L150-L175](https://github.com/pulldown-cmark/pulldown-cmark/blob/48a2767b5b8ab0a4893e80d942e510065889fc6b/pulldown-cmark/specs/math.txt#L150-L175)).
- Expressions may span lines (L93), and their content passes through as-is (L58).
- Block structure wins over math (L241), and tables win over math (L641-L643).

So `$5 and $10` stays text. Inference from those rules: `$5-$10` would parse as inline math `5-`. The extension does nothing for `\(` and `\[`, and it only delimits the TeX: something still has to turn the TeX into Unicode or pixels.

**Is `ratatui-image` useful?** It covers Sixel, Kitty and iTerm2, guesses the protocol from environment variables and then queries, and falls back to half-blocks ([README L27-L33](https://github.com/ratatui/ratatui-image/blob/5d350c695312a15854bf747c860ab704c8d8b522/README.md?plain=1#L27-L33)). It requires ratatui 0.30.1 or later and pulls in `icy_sixel`, `rustix`, `flate2` and `windows` (crates.io, 12.0.0-rc.3). Sixel and iTerm2 are "essentially immediate-mode" ([L40-L48](https://github.com/ratatui/ratatui-image/blob/5d350c695312a15854bf747c860ab704c8d8b522/README.md?plain=1#L40-L48)), so they lose what weave built placeholders for: cells that diff, move, reflow and clip as text. Judgment: it would add only WezTerm, older iTerm2, VS Code and Sixel terminals, none of which the user runs. Half-block rendering of a diagram (two pixels per cell vertically) would make its text unreadable.

**Sizing a tall diagram.** A placement has `c` columns and `r` rows, and "the image will eventually be fit to the specified rectangle, its aspect ratio preserved" ([L751-L752](https://github.com/kovidgoyal/kitty/blob/eb1470d4836ef0f3f51d381d4977f55df4c86fe6/docs/graphics-protocol.rst?plain=1#L751-L752)). The rows a diagram needs are `columns × (cell width ÷ cell height) × (image height ÷ image width)`. At cmux's reported 19×42 px cells, a square diagram 80 columns wide is 1,520 px wide and needs about 36 rows (arithmetic, not a measurement). Three limits apply:

- weave writes a row and a column diacritic in every cell from a 297-entry table ([`graphics.rs` L195-L223](../../tui/src/graphics.rs#L195-L223)), so one placement is at most 297 rows by 297 columns. kitty lets later diacritics be inferred ([L795](https://github.com/kovidgoyal/kitty/blob/eb1470d4836ef0f3f51d381d4977f55df4c86fe6/docs/graphics-protocol.rst?plain=1#L795)), but the row still has to be named.
- Each cell names its own row and column, so a diagram half scrolled out of the fullscreen transcript draws only its visible rows and needs no clipping code. Codex's real placements need explicit clipping (#54216).
- Terminals evict images past a storage quota: 320 MB per buffer in kitty ([L1191-L1199](https://github.com/kovidgoyal/kitty/blob/eb1470d4836ef0f3f51d381d4977f55df4c86fe6/docs/graphics-protocol.rst?plain=1#L1191-L1199)), and 320 MB per screen by default in Ghostty ([`Config.zig` L2515-L2522](https://github.com/ghostty-org/ghostty/blob/cec8b92f1ecd176a20a56aa405021e7ae991b996/src/config/Config.zig#L2515-L2522)).

In inline mode, placeholders written to native scrollback would outlive weave's bookkeeping, and weave deletes every image on exit (commit `d1fcdd2a`). That is the reason weave already keeps inline mode to text labels, and it applies to diagrams as well.

**Footnotes and reference links can change earlier text.** With GFM-style footnotes, a reference to an undefined footnote "renders as literal text" ([v0.13.5 `lib.rs` L700-L715](https://github.com/pulldown-cmark/pulldown-cmark/blob/48a2767b5b8ab0a4893e80d942e510065889fc6b/pulldown-cmark/src/lib.rs#L700-L715)), and the definition usually arrives at the end of the message. So turning footnotes on makes earlier lines depend on later ones, and Codex tracks the same problem for reference-link definitions (15.1). weave writes `[^name]` for a `FootnoteReference` too, so the visible text would not change between the two parses. Any distinct styling, such as a superscript `¹`, would change committed inline lines after the fact. Inference from CommonMark's link reference definitions: without `ENABLE_FOOTNOTES`, a definition of the form `[^1]: https://…` is a link reference definition. It then disappears from the output, and every `[^1]` becomes a link labelled `^1`.

## 22. Fit for the TUI

Judged against weave at `3ee044cb`. The constraints, from the root and `tui/` AGENTS.md and ADR 0018:

- Both screen modes keep working.
- Streaming stays prefix-stable, or holds a block back.
- Agent text is untrusted, and no URL is fetched.
- The TUI follows Codex, and adapted modules carry an upstream header.
- cmux is the main environment, and Rex is coming.
- Every enrichment sits above a text floor, so the source has to stay reachable.

### 22.1 Mermaid

| Option | Coverage | Both modes | Streaming | Without graphics | New dependencies and license | Fit |
| --- | --- | --- | --- | --- | --- | --- |
| A. Adapt `codex-mermaid` as a module | 5 families, small subsets, no subgraphs, at most 16 nodes | Yes | Render closed fences only; hold the fence back in inline mode | Same output everywhere | None (`unicode-width` is already there); Apache-2.0, header comment | Matches upstream; small (about 1,500 lines) and bounded |

Image: merman (or mmdr) to SVG, resvg to PNG, placeholders | Nearly every family | Fullscreen only; inline keeps A or the source | Render on fence close, off the UI thread, cached by (source, width, palette) | Falls back to A or the source in tmux, Zellij, WezTerm, VS Code, Warp, Apple Terminal | B's dependencies plus `merman-render`, resvg, usvg, tiny-skia, fontdb; ELK is EPL-2.0 unless left out; system fonts | Best fidelity where it works. **Recommendation: A now, with the seam built so B or C can replace it.**

1. Adapt `codex-mermaid` into `tui/` with a header naming `codex-rs/mermaid/src/*`. Wire it in as Codex does in `markdown_render/mermaid.rs`:
   - Render only fences whose info string starts with `mermaid` and that have a real closing fence.
   - On any error, print a dim one-line reason and then the highlighted source.
   - Theme the `Node` and `Edge` spans from the syntax theme.
   - Offer a setting, `[tui] mermaid = false`, after `tui.rendering.mermaid`.
2. Extend `commit_boundary` to track open fences instead of blank lines. In inline mode, an open ```` ```mermaid ```` block is held back like a table until its closing fence. If it passes the 16 KiB source limit, it commits as source. Fullscreen needs no hold-back: the live message re-renders and the diagram replaces the source when the fence closes.
3. Decide copy and Find. Judgment: copying a diagram's rows should copy the Mermaid source, as Codex keeps copy sources, and Find should match the rendered labels.

The trade-off is coverage. Diagrams with subgraphs, more than 16 nodes, pie, gantt or mindmap fall back to source.

The weave Host journals every agent message, so the next step can be decided from data. Count the ```` ```mermaid ```` fences in existing journals by family and size, and see how many `codex-mermaid` rejects. If it rejects many, put B behind the same seam, or add C for fullscreen on placeholder terminals. C would extend the thumbnail machinery; it needs no new graphics code.

### 22.2 Math

**Recommendation: adapt Codex's math pre-pass and renderer** (`markdown_render/math.rs`, `math/render.rs`, `math/render/structured.rs`), with their headers.

- It finds `$`, `\(`, `$$` and `\[` in the source before CommonMark escapes destroy the backslash forms.
- It skips code, links and HTML, and rejects money and shell `$`.
- It renders a bounded subset, two-dimensional for display math, and falls back to the verbatim source.
- In inline mode, an unclosed display equation is held back as Codex holds `pending_math_start`.

Do not use `ENABLE_MATH`: it sees only `$` forms, and it would still need this renderer. Inline `$…$` that may span lines (allowed by the pulldown-cmark spec) should be rejected, as Codex rejects it. That keeps per-line prefix stability, because a committed line never contains half a formula.

An image route for display math through RaTeX (MIT, tiny-skia, KaTeX fonts under OFL) is possible in fullscreen only. Judgment: not worth its dependencies until the Unicode subset demonstrably falls short, for example on matrices. opencode's matrix layout would be the cheaper next step.

### 22.3 pulldown-cmark

**Recommendation: upgrade to 0.13.5 in a change of its own**, for the quadratic HTML-comment fix that 0.10.x never received (section 19). Then turn on `ENABLE_GFM` for alerts. Leave off `ENABLE_MATH` (22.2), `ENABLE_SUBSCRIPT` (it changes single-tilde strikethrough), `ENABLE_WIKILINKS` (the source of the 0.13.4 bug) and `ENABLE_SUPERSCRIPT`. Definition lists and footnotes are optional:

- `ENABLE_DEFINITION_LIST` is harmless and rarely matters (judgment).
- `ENABLE_FOOTNOTES` is safe only if references keep the `[^name]` text (section 21).

The edits are the arms listed in section 19. This puts weave ahead of Codex, which is still on 0.10.3, so adapted Codex modules need the `Tag::BlockQuote(_)` change. Judgment: that is a small, mechanical divergence, and security is a reason the follow-Codex rule allows. Stay off `main` until its `ContainerBlock`/`Highlight` changes ship.

### 22.4 Smaller items

- **OSC 8 links.** Adopt Codex's approach:
  - Only `http`/`https` destinations with a host, at most 8 KiB, with control characters rejected.
  - Link bytes added only where text reaches the buffer (ratatui's `ForcedWidth` cells) or the inline history writer. The writer strips control characters from agent spans, so weave's own link wrapper is written around the filtered text.
  - The label alone in recognised terminals (Ghostty, and therefore cmux; kitty; iTerm2; Rex), and `label (url)` in tmux and unknown terminals.

  It works in both modes, and long wrapped URLs become usable. A terminal opens the link itself, so the client still fetches nothing.
- **GFM alerts.** Once `ENABLE_GFM` is on, render the kind as a colored label on the quote's first line (`Note`, `Tip`, `Important`, `Warning`, `Caution`), with the bar in the kind's color. The kind is known at the quote's first line, so this stays prefix-stable.
- **File links.** Show local targets relative to the thread's working directory, as Codex does. Do not emit `file://` links. A weave Host can be a peer on another machine (ADR 0017), so a path in the agent's text names a file on the Host, not necessarily next to the TUI. Codex's local-link module makes the same point about execution-host paths.
- **Markdown images.** Keep `[image: alt] (url)`. Fetching a remote image breaks the no-fetch rule, and a local path may be on another machine.
- **Raw HTML.** Keep it as text, which leaves the source visible. A narrow exception, turning `<br>` into a line break, is a judgment call.

### 22.5 Open questions

- Does iTerm2 3.5 or later draw weave's placeholders? The source has virtual placements (section 20); if it does, `worth_asking` could add `TERM_PROGRAM=iTerm.app` at a version floor.
- Does Rex pass Kitty graphics, and does it set `TERM_PROGRAM=rex`, as Codex's #53725 assumes? weave's probe would skip it either way until it is added.
- With mouse reporting on in fullscreen ([`tui.rs` L117](../../tui/src/tui.rs#L117)), can Ghostty and cmux still open OSC 8 links with a modifier click, or does weave need Codex's in-transcript click handling (#46884)?
- Should copying a rendered diagram or formula give its source or its rendering? Codex keeps copy sources; weave's `DisplayLine` source mapping can carry either.
- Should weave tell agents what this terminal renders, as Codex's flag does, or leave agent output untouched? Judgment: rendering what agents already write fits ADR 0018's text floor better than steering them.
