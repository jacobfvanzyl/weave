# How Terax implements language-server support

_Research snapshot: 2026-08-02. Primary sources only. Terax was traced at commit [`70bfbde84666562cdfca6414636202ea724b85d7`](https://github.com/crynta/terax-ai/tree/70bfbde84666562cdfca6414636202ea724b85d7), including its locked `codemirror-languageserver` 1.22.0 dependency at npm git commit [`65a5d7a8db636047ac90004611d2d818227c3e1f`](https://github.com/FurqanSoftware/codemirror-languageserver/tree/65a5d7a8db636047ac90004611d2d818227c3e1f)._

## Answer

Terax implements a deliberately bounded, opt-in LSP client for its CodeMirror editor. TypeScript owns language detection, activation, protocol behavior, session sharing, and editor UI. A small Rust/Tauri host finds and starts native language-server processes, frames LSP JSON-RPC over stdio, forwards decoded messages through Tauri channels, watches process state and memory, and kills the process tree. There is no LSP integration in the terminal emulator itself. ([Rust command surface](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/mod.rs#L41-L166), [frontend transport](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/transport.ts#L36-L143), [editor mounting](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/editor/EditorPane.tsx#L373-L425))

The current feature covers completion, hover, push diagnostics, same-document highlights, definitions, references, rename, and full-document formatting. It is intentionally not VS Code-class “full LSP”: Terax's contribution guide and roadmap exclude full language-server integration and refactoring engines. ([Terax interactions](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/client.ts#L241-L395), [dependency extension](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/index.ts#L58-L104), [scope statement](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/CONTRIBUTING.md#L109-L116), [roadmap](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/ROADMAP.md#L131-L141))

## Activation and server selection

`lspActivation` persists `enabled` or `dismissed` per server; absence means untouched. For the active local editor file, Terax resolves its language and checks the candidate executable. The status pill offers Enable when found or installation instructions when absent; it copies commands and links documentation but does not install anything. Settings can enable, disable, redetect, restart, and add custom stdio servers. ([activation state](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/settings/store.ts#L181-L214), [hint state machine](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/useLspHint.ts#L15-L66), [status pill](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/components/LspStatusPill.tsx#L30-L282))

There are 18 built-in presets covering TypeScript/JavaScript, Rust, Pyright, Ruff, Go, C/C++, Zig, Lua, Ruby, PHP, YAML, shell, JSON, CSS, HTML, Svelte, Vue, and Swift. Each maps Terax language IDs to LSP IDs and declares executable arguments and project-root markers. Users can add a command, whitespace-split arguments, extensions, language ID, and root markers. When multiple servers claim a language, an enabled candidate wins; otherwise the first non-dismissed preset wins, so Python uses either Pyright or Ruff, not both. ([preset registry](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/presets.ts#L3-L274), [selection rule](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/presets.ts#L283-L321), [custom-server form](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/settings/components/LspServersGroup.tsx#L145-L248))

The feature remains lazy until a ready document has an enabled server. Files over 4 MiB disable both syntax highlighting and LSP. Only local workspaces are accepted; WSL is explicitly rejected. ([lazy hook](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/useLspExtension.ts#L8-L51), [size gate](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/editor/EditorPane.tsx#L91-L96), [WSL rejection](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/mod.rs#L60-L80))

## Process and protocol flow

On Unix, Terax captures the login-shell environment once because GUI applications may lack the user's PATH. Detection and spawn resolve the executable from that environment. The root resolver walks upward to the nearest preset marker but stops at the home directory; no marker means no session. Rust canonicalizes the chosen root and requires it beneath an authorized workspace, preventing `..` and symlink escapes. ([environment capture](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/env.rs#L1-L108), [root resolver](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/mod.rs#L111-L209), [workspace authorization](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/workspace.rs#L10-L95))

Rust starts the executable directly—no shell—with the canonical root as cwd and piped stdin/stdout/stderr. Unix servers get their own process group; Windows attempts a kill-on-close Job Object. The stdio codec adds and incrementally parses LSP `Content-Length` frames, rejects malformed/non-UTF-8 payloads, and caps messages at 64 MiB. Tauri channels carry decoded JSON payloads and exit information. ([spawn lifecycle](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/session.rs#L33-L191), [framing codec and tests](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/framing.rs#L1-L222))

The frontend answers a narrow set of server-to-client requests: configuration items get `null`; progress creation, registration, unregistration, show-message requests, and workspace-folder requests get a null result; unknown methods get `-32601`. This is compatibility scaffolding, not full dynamic-capability support. Terax subclasses the dependency's client to add a host PID, diagnostics/references capabilities, references requests, didClose/didSave, and shutdown/exit. ([request handling](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/transport.ts#L73-L105), [client subclass](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/client.ts#L397-L447))

## Sessions and document synchronization

Sessions are keyed by `(server preset, project root)` and shared across open documents. Acquisition is deduplicated, each preset is capped at four roots, and URI reference counts drive didClose. When the last document closes, a three-minute timer performs shutdown/exit and then kills the transport. Disabling stops sessions; restart bumps a generation so open editors reacquire. Unexpected exits back off for 2, 10, then 30 seconds; three crashes within five minutes cause Terax to give up until explicit restart. ([session acquisition](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/sessionManager.ts#L14-L155), [shutdown and restart](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/sessionManager.ts#L260-L394))

Each CodeMirror document sends full text in didOpen, incremental range edits in didChange, didSave only after Terax's conflict-checked disk write, and didClose on release. A likely dependency defect is that didOpen uses version 0 and the first didChange also sends version 0 before incrementing, while LSP requires increasing versions; this is a source comparison, not a reproduced server failure. ([Terax sync options](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/sessionManager.ts#L119-L151), [dependency sync](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/plugin.ts#L398-L497), [save notification](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/editor/lib/useDocument.ts#L61-L97), [LSP version rule](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#versionedTextDocumentIdentifier))

## Implemented UI and limits

- Completion uses CodeMirror's popup, server trigger characters, primary/additional text edits, and lazily resolved documentation; snippet support is advertised false. Hover renders documentation and Terax syntax-highlights code blocks. Diagnostics become CodeMirror lint markers plus status-bar error/warning counts. ([completion](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/plugin.ts#L540-L688), [hover decoration](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/client.ts#L112-L181), [diagnostics](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/plugin.ts#L772-L821))
- F12/Cmd-click definitions and Shift-F12 references share a multi-result picker; external results open another editor tab. F2 rename is **current-document only** because the dependency ignores workspace edits for other URIs. Shift-Alt-F and format-on-save perform full-document formatting; no LSP range-format UI is wired. ([navigation](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/client.ts#L241-L395), [rename filter](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/rename.ts#L20-L67), [awaited formatter](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/client.ts#L72-L110))
- No code-action/quick-fix, signature-help, semantic-token, inlay-hint, code-lens, symbol, implementation, call-hierarchy, workspace-diagnostic, or general multi-file workspace-edit path was found. Type-definition support inherited from the dependency navigates only inside the current document. ([actual extension set](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/index.ts#L58-L104), [same-document dependency navigation](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/plugin.ts#L694-L773))

## Resource and security boundaries

Servers have a 4 GiB default leader-RSS budget after a two-minute grace; Rust Analyzer requests 3 GiB. Sampling excludes helper-process RSS, so this is a guardrail rather than a tree budget. App exit explicitly kills every session. ([memory watchdog](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/session.rs#L205-L243), [app-exit cleanup](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/lib.rs#L322-L334))

Workspace authorization constrains cwd, but servers are trusted native processes: they inherit the captured environment and are not filesystem/network sandboxed. Also, although Terax passes `allowHTMLContent: false`, dependency 1.22.0 converts server-supplied Markdown with `marked.parse` and assigns it to `innerHTML` without a sanitizer visible in that path. A malicious server could therefore attempt webview markup injection through hover/completion documentation. This is a source-level concern, not a demonstrated exploit. ([spawn environment](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src-tauri/src/modules/lsp/session.rs#L69-L103), [Terax option](https://github.com/crynta/terax-ai/blob/70bfbde84666562cdfca6414636202ea724b85d7/src/modules/lsp/lib/sessionManager.ts#L119-L151), [dependency Markdown rendering](https://github.com/FurqanSoftware/codemirror-languageserver/blob/65a5d7a8db636047ac90004611d2d818227c3e1f/src/plugin.ts#L498-L536))

## Verification

The trace followed active-file activation through discovery, root authorization, shared-session acquisition, CodeMirror synchronization, Tauri transport, Rust process hosting, editor interactions, and shutdown. The exact locked dependency source was inspected to distinguish advertised capabilities from working UI and to establish rename, type-definition, versioning, and Markdown-rendering limits. Terax's Rust tests cover framing, roots, binary resolution, process cleanup, RSS, and workspace authorization. Live interoperability across all presets was not claimed.
