# Protocol precedents

These are design references, not tested replacements for the Viz capture or native decoder. The live transport remains gated on actual offline reconstruction.

Microsoft's Composited Remoting V2 distinguishes connection-scoped channels from channel-scoped resource handles. Creation and destruction are explicit, ordered messages. Destroying a handle can leave its object alive while other objects reference it. The useful lesson for this spike is to separate resource identity, addressability and physical lifetime; a Chromium import ID, a remotely cached generation and a live GPU allocation should not be treated as one thing. [MS-RDPCR2 object handles](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpcr2/fdc5916c-5005-4a4b-a90d-b5d0d6df6475).

That protocol's surfaces and visuals model a composed desktop. It also includes its own glyph-run and rasterized glyph-cache protocol. Adapting Viz quads to those semantics would require a translation and rendering implementation, not merely choosing an established framing format. The document is a useful precedent for retained graphics; these sources do not establish a ready Chromium-to-Metal backend. [Surface management](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpcr2/80a199ac-359a-493c-9983-8d619af23507), [drawing text](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpcr2/7f0a75b2-6134-41b5-bf09-0bc6d293adc9).

Mozilla's rendering overview describes a self-contained WebRender display-list blob crossing IPC and the C++/Rust boundary, followed by scene construction, frame building and GPU work including glyph-atlas preparation. This supports using explicit serialization and independent resource management, but it is a different boundary from exporting Chromium's already-rasterized tiles. A WebRender consumer is not automatically a Viz-quad consumer. The overview contains historical Firefox process-model details, so it is used here as an architectural explanation, not a current Firefox deployment audit. [Mozilla rendering overview](https://firefox-source-docs.mozilla.org/gfx/RenderingOverview.html).

For the initial Viz experiment, the resulting design inference is deliberately modest: retain immutable raster generations, fully describe the selected frame's dependencies, make those resources available before rendering the frame, and reset the client namespace on a new capture session. Measure complete-frame metadata before adding scene-delta operations or adopting a larger graphics protocol. These are proposed transport principles; the current implementation is still a file capture with a sequential offline decoder.
