# WVE-81: paired USB reconnect and automatic control

22 September 2026. Requested behavior: while the Mac companion is open, a
previously paired USB device opening Trackpad connects and starts control
automatically. Built-in and external Mac pointing devices remain usable.

## Implementation

- App-local Keychain installation identity and peer secrets replace per-session
  approval. The earlier preview had no durable pairing to migrate, so one new
  **Pair and connect** confirmation is required.
  iOS uses its app-private, unlocked/device-only data-protection Keychain.
  The Mac uses the non-synchronizing login Keychain with its code-signing access
  control, avoiding a Mac development provisioning profile for this local app.
  Keychain read failures stop pairing rather than replacing its identity or
  falling back to another store.
- Wire v3 uses mutual HMAC-SHA256 proofs with fresh nonces and session/identity/
  role binding. The host waits for confirmation of its proof before enabling
  control. Initial secret exchange requires explicit mobile approval over USB.
- The Mac checks USB discovery roughly once per second and probes paired serials
  only, rotating candidates so an inactive device does not starve another.
  An occupied connection is never taken over automatically.
- Automatic control requires Accessibility and an active Mac session. Explicit
  stop/disconnect pauses automatic control until resume or companion restart.
  Mobile disconnect pauses listening until reconnect or a new app opening.
- Backgrounding, transport loss, timeout, and sleep release session input;
  reconnect starts with fresh gesture state. Lock handling supplements documented
  sleep/session notifications with best-effort distributed lock signals and a
  console-state check; it is not a documented secure-lock API guarantee.
- Quartz's local event filters permit mouse, keyboard, and system events during
  both posting suppression states, with a zero suppression interval. Local
  observers return events unchanged, resynchronize the cursor, and cancel mobile
  momentum when another pointer/scroll source is used. They do not grab devices.

USB's initial trust boundary is the OS-paired physical cable route through
usbmuxd. Authentication does not add encryption or per-frame integrity. Wi-Fi
remains unimplemented and requires its own authenticated encrypted transport.

## Automated validation

42 focused Swift tests pass. Ten new tests cover initial consent, complete
mutual authentication, automatic reconnect without retransmitting secrets,
session/nonce replay rejection, proof-role separation, unknown hosts, wrong
keys/identities, secret replacement, persisted/wire serialization, old-version
rejection, retry rotation and gating, and Quartz local-event filter read-back.
The Quartz test constructs an event source; it does not post events.

Signed Release builds for Mac and iOS pass, and both bundle signatures verify.
The Mac update is installed at the stable `~/Applications/Weave Trackpad.app`
path and running normally. Its initial local Keychain write and subsequent
read after a companion restart succeeded (`pairingStorageAvailable: true`).
Accessibility remains enabled.

The iPad installation attempt failed with CoreDevice error 4000: the device
disconnected immediately after the tunnel connected. A subsequent usbmuxd
inventory contained no USB devices. The Mac also reports an inactive desktop
session, so automatic control remains gated off. The user has been asked to
wake/unlock the Mac and reconnect the unlocked iPad. The iOS build is ready but
not installed; no physical automatic-connection success is claimed yet.

23 September follow-up: the reconnected iPad accepted the signed update and
launched normally. The Mac companion's native UI is accessible again and shows
the USB device. Selecting Connect reached **Approve pairing on your mobile
device**. Initial pairing confirmation and the automatic reconnect check are
pending at that point; the installation blocker is resolved.

The user approved initial pairing. The Mac reported one paired device and
`controlEnabled: true`. A normal iPad app relaunch through devicectl then
reconnected without any Mac Connect/control-toggle action or further mobile
approval: the native UI showed **USB connected • controlling this Mac** and
the diagnostic automatic-connection counter increased from 0 to 1. This verifies
saved-pairing reconnection through the physical USB route.

Explicit Mac Disconnect remained paused during the subsequent observation
instead of bouncing back into a connection. **Resume automatic connections**
restored authenticated control. Quitting and relaunching the companion also
restored the saved pairing and automatic control with the iPad app still open.
Both apps are left connected in normal mode. Physical built-in trackpad/external
mouse coexistence and interruption scenarios below still need hands-on acceptance.

## Hardware acceptance checklist

- [x] Pair once on iPad Air M3/Pencil Pro with the M4 MacBook Air and upper Dell.
- [x] Relaunch the mobile app: no approval prompt or control
  checkbox action, with authenticated automatic control recorded on the Mac.
- [x] Restart the companion: the saved pairing still reconnects automatically.
- [x] Explicit Mac disconnect stays paused until resumed; no immediate reconnection.
- [ ] Background/foreground the mobile app without process relaunch; test its disconnect/reconnect action.
- [ ] Alternate iPad movement/click/scroll/Pencil with physical built-in trackpad
  and an external mouse; verify local controls still work normally.
- [ ] Cable removal while dragging/scrolling, sleep/lock/unlock, and permission loss
  release input and obey reconnect/control gates.
- [ ] A second attached paired device cannot replace an active session; an unknown
  device never starts control automatically.
