# WVE-81: pointer and scroll motion increment

22 September 2026. Builds use Xcode 26.6 / Swift 6.3.3, signed Release configuration.
Hardware: MacBook Air M4 on macOS 26.6.2; iPad Air 11-inch M3 with Pencil Pro,
on iPadOS 27 beta. Built-in display: 1470×956 points at 60 Hz. Upper Dell
S3220DGF: 2320×1305 points at 120 Hz, origin (-437, -1305).

## Implemented

- Source-timed vector pointer gain: smoothstep from 0.85 at 30 points/s to 3.2 at
  900 points/s, with a 12 ms velocity filter and a separate 0.25–3× speed setting.
  Position itself is not smoothed or held for a display frame. Linear mode uses
  the previous 1.7 multiplier. Absolute Pencil mapping bypasses these dynamics.
- Mac-owned double-tap/drag decisions use `NSEvent.doubleClickInterval` (0.5 s on
  this Mac) and an 18-point proximity limit. The mobile recognizer retains a
  separate 0.3 s tap-duration limit and 6-point movement slop.
- Momentum estimates velocity over up to 80 ms of source history, clears it on
  reversal, accounts for a pause before lift, and waits for all fingers to lift.
  Lingering contacts beyond 80 ms prevent a fling. Lift positions cannot inject
  new motion. Starting speed is capped at 6000 points/s with a 40 points/s minimum.
- The Mac integrates exponential decay with a 0.24 s time constant, using a
  120 Hz common-mode timer only while momentum is active. It stops below
  8 points/s or after 2 seconds. A scheduler stall over 100 ms cancels the tail.
  These coefficients are a tunable starting point, not measured Apple defaults.
- Quartz contact phases use 1/2/4 and momentum phases 1/2/3 in their distinct
  fields. Fractional scroll residuals are conserved within each direct or
  momentum phase; less than a pixel can be discarded at a phase boundary.
  Zero-delta lifecycle events are emitted. Both axes are preserved; receiving
  applications own axis locking, content bounds, and bounce.
- A coherent cursor accumulator avoids rereading a lagging cursor for each
  posted delta. External mouse motion resynchronizes it; display bounds constrain
  it. Own events carry a source tag so they cannot overwrite the accumulator
  through mouse monitors. No keyboard events are monitored.
- A fresh contact cancels momentum before recognition and suppresses its tap.
  Release/control disable, disconnect, mode/mapping/settings changes, sleep, and
  session deactivation cancel active input. An additional best-effort distributed
  screen-lock notification is observed; this is not a documented lock API and
  physical lock/unlock coverage remains to be verified.
- Persistent local controls and a native comparison/recording window are included.
  Wire v2 adds contact boundaries. Both installed apps must use this version.

## Automated and UI evidence

28 focused Swift tests pass. These cover frame validation, mapping generations,
Pencil releases, double-tap drag through recognizer and session, two-finger tap,
source-time pointer gain under delivery jitter, cadence independence, diagonal
invariance, linear mode, pause/reversal/stale scroll data, fractional conservation,
lift noise, stop-touch click suppression, interruption terminal events, and
Core Graphics to AppKit phase/precise-delta conversion.

Signed Mac and iOS Release builds succeed. The installed companion's controls and
native test window were visually checked. UI automation clicked the target and
scrolled the native view; its optional recording saved 26 pointer/button/scroll
events. This checks the local observation surface, not physical trackpad or iPad
motion feel. No automatic event injection was run against unrelated apps.

## Remaining physical acceptance

Compare native and USB iPad trials in the test window, Safari, Finder, and a
scrollable editor/two-axis canvas. Check slow targeting, fast travel across the
built-in and upper Dell, diagonal movement, drag precision, repeated flicks,
pause-then-lift, touch-to-stop without click, and settings changes mid-gesture.
Record chosen speed settings and keep Apple's global preferences unchanged.

Also exercise physical USB removal, app backgrounding, screen lock/unlock, and
permission revocation during momentum, then verify fresh connections start with
control disabled. Pointer burst behavior and resynchronization with the physical
trackpad need hands-on confirmation. Finger coalescing remains disabled pending
measurement of synchronized two-finger centroids. iPhone-specific feel, exact
Apple curve equivalence, and visible end-to-end latency have not been established.

## Real USB receive-only check

The signed iPad build was installed and launched successfully with the existing
VeeZee development account; the Mac bundle was replaced at its stable path and
its signature verified. Accessibility remained granted.

With both apps in explicit receive-only diagnostic mode, the real `USB/usbmuxd`
route delivered the synthetic source-timed burst and produced exactly one
momentum begin, 129 momentum changes, and one momentum end. At completion,
`momentumActive` was false and posted-event counts were zero. There were 21 input
messages including the view's setup reset. The mobile diagnostic waits 200 ms
after ready so that setup reset cannot cancel the synthetic fling; ordinary
input is never delayed by this diagnostic wait.

Evidence snapshot: ignored `.local/acceptance/motion-usb-diagnostic.json`.
This establishes framing, reducer integration, and the Mac timer over the actual
cable route. It does not establish physical-touch feel or destination-app input
posting. UI read-back confirmed an acceleration preference survived app restart;
settings were then restored to their defaults for user tuning.

## Normal-session observation

After returning both apps to normal mode, UI read-back confirmed the user-approved
USB session was controlling the Mac. At 2026-09-22T17:54:24Z, diagnostics recorded
1653 input messages, 2334 posted events, and
789 posted momentum events. Processed momentum phases
were 17 begins and 17 ends;
`momentumActive` was false at the snapshot. Defaults
remained at 1× speed with acceleration, natural scrolling, and momentum enabled.

This is evidence of the normal mobile-to-Mac posting path while the user tried
the app, beyond the receive-only synthetic check. It does not substitute for
the user's assessment of comfort or the remaining interruption/cross-app trials.
Snapshot: ignored `.local/acceptance/motion-normal-session.json`.

## User acceptance

The user tried slow pointer movement, a fast sweep, and a two-finger flick with
a touch to stop, and reported **“Feels good.”** The default pointer/scroll feel
is accepted for this iPad/Mac setup. This does not extend acceptance to iPhone,
all destination applications, lock/unlock, or the other interruption trials.
